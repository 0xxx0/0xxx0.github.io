## PURPOSE

This thread is the repository migration, archaeology, quarantine and promotion layer for 0xxx0 / FIELD.

It exists to reduce:

- lost lineage
- false project fanout
- duplicate artifacts
- stale canonical pointers
- source/provenance loss
- accidental promotion of generic or nostalgic junk
- repeated rediscovery of already-rejected candidates

It increases:

- exact recoverability
- useful runnable surfaces
- donor quality
- confidence in the Field Index
- bounded handoff packets to other fronts

## PRIMARY LAW

**RECOVER BEFORE INVENTING.**

Then:

`INGEST → PROVE IDENTITY → PRESERVE SOURCE → CLASSIFY → COMPARE MECHANISM → PROMOTE OR QUARANTINE → RETURN`

## WHAT THIS THREAD OWNS

1. Exact-source archaeology across Library, Drive and repository.
2. Hash / byte-equivalence / duplicate-family verification.
3. Source, spec, image and receipt evidence separation.
4. Head / donor / recover / import / merge-candidate / quarantine classification.
5. Field Index population and route QA.

## WHAT IT DOES NOT OWN

- Redesigning current heads merely because old source was found.
- Making every recovered file public.
- Treating visual polish as mechanism.
- Converting every analogy into architecture.
- Bulk deletion, mass rename or destructive dedup.
- Publishing private raw conversations or personal material as archaeology.
- Reviving a historical project solely because it is strange, old or emotionally charged.
- Opening new fronts when a donor can be frozen and held.

## EVIDENCE CLASSES

### BYTES
What actually existed: exact source, executable, assets or archive.

### SPEC
What it meant or promised. Original notes and later reconstruction remain distinct.

### IMAGE
What it looked like. Screenshot evidence does not prove executable behavior.

### RECEIPT
What actually happened in a particular run, test, replay, build or RETURN.

## PROMOTION GATE

An artifact may move toward the active/public surface only when it clears:

1. **IDENTITY** — exact object/version is distinguishable.
2. **PROVENANCE** — source/evidence class is explicit.
3. **MECHANISM** — surviving operation can be named.
4. **PAY RENT** — adds capability, evidence, lineage, constraint, or a required source.
5. **RETURN** — effect can be verified without erasing the source.

Failure at the gate does not imply deletion.

## ZONES

### TROPHY
Exact/frozen artifact that earned survival.

### EXPEDITION
A concrete exact-source gap worth pursuing.

### QUARANTINE
Preserved without promotion. No beautification debt.

### ATTIC
Rejected, generic or weakly evidenced candidates kept as negative knowledge.

## EXCURSION RETURN CONTRACT

A migration excursion should return at least one of:

- exact lost artifact
- exact duplicate collapse
- lineage correction / contradiction
- stale-pointer repair
- bounded donor/implementation packet
- explicit blocker with evidence
- rejected-candidate receipt

If it returns only “interesting old things,” stop and classify before continuing.

## OLD-JUNK RULE

**OLD ≠ IMPORTANT. WEIRD ≠ WORTHLESS. SHINY ≠ TRUE.**

Historical hacks are allowed to be ugly, broken, partial, embarrassing or overbuilt. Their value is determined by surviving mechanism/evidence, not by whether they deserve restoration.
