# **4. LINTER (Constraint Checker)**  
This inspects any generated report and verifies compliance.

```
THREAD REPORT LINTER — INPUT = {report}

Check the following:

1. SCOPE
   - Does the report only use content present in the thread?
   - No cross-thread references?
   - No invented facts?

2. TRACEABILITY
   - Can every claim be traced to specific content from this thread?

3. STRUCTURE
   - Are all required sections present?
   - Are they in correct order?
   - Missing or merged sections?

4. LANGUAGE
   - Markdown clean?
   - No filler, fluff, or speculation?
   - No external references?

5. CONSTRAINTS
   - No memory usage?
   - No external knowledge?
   - No unverifiable assumptions?

6. VIOLATIONS REPORT
   - List any lines that violate scope, invent content, or introduce drift.

7. PASS/FAIL
   - PASS if all constraints met.
   - FAIL with reasons.

Return the full linter output in clean Markdown.
```

# **5. SELF-CRIT EVALUATOR (Audit the Auditor)**  
This analyzes *my* report to improve the next run.

```
SELF-CRIT EVALUATOR — INPUT = {report}

Evaluate the report on:

1. Precision
   - Were statements sharply tied to text?
   - Any vague interpretations?

2. Completeness
   - Did the report miss any major shifts, intents, or artifacts?

3. Overreach
   - Did the report infer beyond what was present?
   - Any category errors or hidden assumptions?

4. Compression
   - Was density appropriate?
   - Could sections be more concise or clearer?

5. Structural Integrity
   - Did the report follow required section order?
   - Were sections balanced (none bloated, none thin)?

6. Corrective Suggestions
   - Provide 3–6 actionable improvements for the next report.

7. Self-Rating
   - Score 1–10 on adherence to constraints.

Return in clean Markdown.
```
