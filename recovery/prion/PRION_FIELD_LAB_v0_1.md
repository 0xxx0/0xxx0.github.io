# PRION FIELD LAB v0.1
## ethical active-measures / learning-transfer prototype

**Status:** proposed prototype assembled from the Prion/YAW, emotion-map, movement-learning, maker/fold, spatial-state, and epistemic-security threads.

**Scope:** self-directed or explicitly consensual practice only. No covert persuasion. No “infection” as a virtue. The system succeeds when the operator can be **understood, tested, mutated, refused, and retired**.

---

# 0 — Core correction

Prion Protocol is not “active fiction.” Fiction is one carrier.

The operational system is:

```text
SEED → EMBODY → EXTERNALIZE → PLACE → TRIGGER
     → ENACT → TRACE → MUTATE → VERIFY → RELEASE → RESEED
```

A **Prion Packet** is the smallest transmissible unit:

```text
CUE
ACTION
TRACE
FALSIFIER
MUTATION PATH
EXIT
```

If one of those is missing, the packet is either inert, dogmatic, or hard to audit.

---

# 1 — The five fields

The same operator should survive translation across distinct fields.

## BODY
movement, coordination, balance, rhythm, perception-action coupling.

## AFFECT
feeling as signal; appraisal as hypothesis; action as lever.

```text
FEELING → APPRAISAL QUERY → REALITY TEST → LEVER → ACTION
```

## SPACE
room, tool placement, light, sound, friction, route.

```text
LOCATION → CUE → ACTION → TRACE
```

## INFORMATION
claim, source, uncertainty, contradiction, prediction.

```text
OBSERVED / REMEMBERED / INFERRED / REPORTED / PREDICTED / TESTED
```

## CRAFT
material, constraint, operator, object, verification.

```text
MATERIAL → CONSTRAINT → TRANSFORM → ARTIFACT → TEST
```

The prototype is successful only when one distinction moves through at least **three fields** without becoming merely metaphorical.

# 2 — The learning engine

## CALIBRATE
Notice the current error without trying to erase it.

## STABILIZE
Repeat one clean version while keeping effort easy enough for precision.

## VARY
Change one variable at a time.

## TRANSFER
Apply the relation to a task whose surface features differ.

## RELEASE
Stop rehearsing; preserve the trace; let sleep/rest separate useful structure from foreground effort.

This deliberately avoids “more is better.” Week 1 uses short, low-fatigue skill samples. It is not a complete exercise programme.

---

# 3 — Evidence-informed design choices

### External focus
Motor-learning meta-analysis generally favors focusing on the intended effect of movement rather than micromanaging body parts. Prototype implication: cue the **target / path / sound / object effect** first; use body-part cues only when genuinely needed.

### Variation
Recent contextual-interference meta-analyses support varied/random practice overall, but transfer effects in young participants were negligible in one 2024 review. Prototype implication: **do not worship randomness**. Stabilize first, then vary one dimension deliberately.

### Observation + imagery
Observation can support motor adaptation but is weaker than actual physical practice; recent action-observation + motor-imagery reviews are promising but heterogeneous. Prototype implication: use watch/imagery as a **supplement**, not a substitute.

### Sleep / release
Sleep supports learning and memory consolidation; established teen guidance is 8–10 hours per 24 hours. Prototype implication: no “train all night” mythology. The engine explicitly contains `SLEEP / RELEASE`.

### Tai Chi / slow-form work
A 2025 review in children/adolescents suggests possible benefits for balance, flexibility, motor skills and psychological outcomes, but evidence quality and safety reporting are not strong enough to treat it as superior. Prototype implication: use **slow weight-shift / continuous-form practice** as one low-risk movement surface, not as a medical claim or magical mechanism.

# 4 — Transfer checksum

Do not ask “did I like the drill?” Ask whether the operator survived.

A packet progresses through qualitative states:

```text
ABSENT → SEEN → ENACTED → RECALLED → TRANSFERRED → MUTATED → RETIRED
```

No streaks. No points. No “level.”

A transfer is provisionally real when:
- the cue can be recalled after a gap;
- the action can be reproduced without the original explanation;
- the operator appears in a different field;
- a failure case can be named;
- the user can alter or refuse it without breaking the system.

# 5 — Prototype operator set

## O1 CONTACT
received signal ≠ interpretation.

## O2 EXTERNALIZE
move useful structure out of working memory and into a visible object.

## O3 AIM
attend to intended effect.

## O4 VARY
change one parameter while preserving the relation.

## O5 DISCRIMINATE
generate at least two live explanations and seek the smallest distinguishing observation.

## O6 ASSIGN
convert vague collective intention into a named local function.

## O7 TRACE
record only the decision-relevant delta.

`BEFORE / MOVE / AFTER / SOURCE / UNCERTAINTY`

## O8 SLEEP
release the foreground model; return later and test what survived.

# 6 — Ethical hyperstition demo

A tiny transparent representation is deliberately allowed to help make itself true.

Example:

> **WHEN this folded card is beside the door, THEN before leaving I do one 45-second coordination sample and mark only whether I started.**

This is not covert conditioning: the rule is visible, chosen, local, removable, and expiring.

If the card changes behavior, representation has become causal. That is a small testable hyperstitional loop without pretending belief created reality by magic.

---

# 7 — Field cassette

A cassette is a **portable capability bundle**, not a fixed inventory.

Prototype needs only ordinary safe items:
- phone/timer;
- pencil/marker;
- paper/index cards;
- removable tape;
- soft rolled socks or another soft lightweight object;
- small envelope/pouch.

Capabilities: `CUE · TARGET · TRACE · FOLD · MOVE · RELOCATE · EXPORT`

Manual first. Sensors later. The room is already an interface.

---

# 8 — Bendemeer / Blight room integration

Do not begin with 3D modelling or automation. Start with a **2D manual room graph**:

```text
NODE = place/object
EDGE = transition
STATE = ready / blocked / active / sleeping
CUE = visible trigger
TRACE = evidence of use
```

Choose only three loci for Week 1:

```text
DOOR      transition / cue
DESK      craft / trace
OPEN AREA body / movement
```

Graceful degradation: `automation → phone → paper → memory`

---

# 9 — Security / anti-capture layer

Every packet has an immune system. Before promotion:

```text
SOURCE?         where did this come from?
INDEPENDENT?    are “multiple confirmations” actually copies?
FRESH?          does age matter here?
CONTRADICTION?  what does not fit?
FALSIFIER?      what would count against it?
EXIT?           how do I stop the packet?
```

A successful Prion teaches resistance to itself.

---

# 10 — Week-1 research question

> Can a transparent cue + tiny enactment + trace cause a **portable operator** to appear in a second domain after a delay?

Primary observations:
- started / did not start;
- operator recalled without card;
- transfer example appeared / did not;
- failure case identified / not;
- packet mutated or retired.

No appearance metrics. No calorie metrics. No maximum-effort tests.

---

# 11 — Week-1 build target

By the end of the week there should be:
1. one working offline demo;
2. one physical fold/cassette;
3. seven daily traces;
4. three transfer examples across different fields;
5. one packet deliberately retired;
6. one packet retained because it changed a real move.

**Stop condition:** if the system generates more terminology than changed behavior, stop adding machinery.
