# FOLD//BLOOM — convergence audit / repair 0.1
2026-10-20 · bounded implementation branch · no new engine, source store or route

## Actual problem
The repository contains many capable but disconnected presentations of **one held object**. Shipping more rings, repainting the index or inventing an agent controller does not restore a useful entry operation. The original job was not a music visualizer: it was controlled transformation through *unequal* representations with stable identity, authored changes, and exact RETURN.

Original commitment (recovered from the existing convergence packet):
`SOURCE → ADDRESS → APERTURE → PROJECTION → HUMAN ACTION → RETURN`

A projection is justified if and only if it makes a named action cheaper **and** preserves the source's identity, focus/address, provenance and return path. No host gains authority by rendering another host's evidence.

## Bounded delta on this branch
1. `/docs/`: first-use `TRY RSVP` uses a bundled short text without network; FAST explicitly chooses `WORD` at 900 WPM; mount the existing modern `readfield-controls.js` controls.
2. `/fold-bloom/listen/`: explicit `TRY DEMO · LOCAL` generates a deterministic offline six-second WAV; preserve the same source-hash path as uploaded audio. Analysis worker request IDs prevent stale results from replacing a later source. Playback failure gets an actionable message.
3. `/fold-bloom/lens/`: start in focused sample view with LAB accessible but not default.
4. `/fold-bloom/`: remove false `?source=example` landing link.
5. Extend `listen-readfield-check` to gate source invariants and phone-width browser first use.

## Exact acceptance sequence
**P0 Cold opening (phone-width Chromium):**
- READ `TRY RSVP` → word units advance at 300 WPM, STOP, regress one unit, source unchanged.
- LISTEN `TRY DEMO · LOCAL` → exact hash present and same-origin Blob bound; honest `AUDIO_ONLY` if browser decoding stalls; hardware audible playback remains unverified.
- SCALE LENS → sample source navigable and LAB closed initially.

**P1 Cross-host continuation (existing gate, not newly claimed):**
- LISTEN exact local hash → MARK beat/phrase → LIVE receives same source → return reopens same address and mark.
- READFIELD → change WORD/SENT/PARA ↔ RSVP ↔ VOICE/LOCI → unchanged identity and cursor; no stale handoff accepted.
- Android actual-device test is required for background playback/permissions/gesture behavior. Headless is not a physical-device pass.

## Falsifiers / hard stops
- Any run has an uncaught JS error or a working control with no perceptible consequence.
- A stale analysis request overwrites newer source, or a handoff silently changes source hash / focus / provenance.
- On phone, SOURCE/PLAY/MARK/RETURN are unreachable after load.
- The change requires a new global store, universal event bus, new media provider, AI generation credit, credentials, or unmeasured composition machinery.
- If first-use browser smoke fails, **do not merge** or promote the UI as repaired. Audio output/clock advance on actual hardware is explicitly outside headless CI proof. Return only failure + exact bounded patch.

## Next highest-return experiment (only if P0 passes)
Choose one user-owned complete song and one short technical passage; annotate an audible turn, move into LIVE, then use READFIELD to pause and mark a claim. Export a minimal **same-source / same-address / changed-projection / authored-action / RETURN** receipt, measure time-to-first-action and re-entry failures. Judge on actual phone; delete no existing engines until a new representation proves it replaces them.

## What this is not
Not a completed interaction redesign, not proof of device functionality, not a port of Magenta, not new music generation, not a claim that all surfaces converge already. It is a falsifiable repair and one active user-reentry thread.
