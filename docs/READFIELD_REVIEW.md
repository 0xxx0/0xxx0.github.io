# READFIELD: interpretation beside an exact work

Selected brief, 27 October 2026: reduce the existing `/docs/` reader into a compact instrument for reviewing documents and artifacts, defining what matters, annotating an interpretation, and seeing that work accumulate in a glyph. Preserve the reader's source, native cursor, scope, voice/RSVP and exact return. No new route or source owner.

Assumptions: annotations express the reader's interpretation; advancing playback is not evidence of understanding. Literal search is not semantic relevance. An idea marked APPLIED is a human declaration, not a measured effect. Input is text/Markdown/JSON/CSV/source code; PDF/EPUB extraction is not implemented here.

## References learned from

- Steven Wittens, [Tools for Thought](https://acko.net/files/gltalks/toolsforthought/): operations change the represented quantity. Here angle maps character position; arcs map authored ranges; union coverage computes characters actually annotated. No inferred semantic geometry.
- [LiquidText](https://www.liquidtext.net/): bring excerpts together while preserving original context. Here REVIEW folds source-addressed passages and human interpretations into one source-ordered reading; context opens at the exact range start.
- [Readwise Reader](https://docs.readwise.io/reader/docs/faqs/highlights-tags-notes): document notes, passage notes, keyboard reading and returning to highlights. Those capabilities already exist in external tools; this work claims a native FIELD reduction, not category novelty or superiority.
- Matuschak / Nielsen, [Transformative Tools for Thought](https://numinous.productions/ttft/): active retrieval differs from passive exposure. This implementation records explicit interpretation and open questions; it does not implement spaced repetition or demonstrate learning gains.

## Minimal organism / survivor catalog

`docs/index.html` exposes a bounded bridge to its existing raw source, SHA-256, native focus and `FieldSourceTrail`. It remains the source owner.

`lib/read-trail.js` retains its existing schema and storage keys, extending normalized marks with exact quote, revision, end character, kind and question state, plus per-work purpose, literal terms and working conclusion. Native bookmark toggles cannot delete revision-bound annotations. Full local source is session-only; saved quotes are device-local excerpts. Existing 64-mark bound remains explicit.

`lib/readfield-review.js` adds a source-native interpretation projection. NOTE, QUESTION and APPLIED have visible labels and shape equivalents. The current glyph uses the existing aperture SVG: outer ticks are literal matches; inner arcs are annotated character intervals; hollow circles are unresolved questions; squares are applied ideas. Only a matching revision AND exact quoted range contributes to annotation coverage. Overlap is counted once. Stale/legacy marks remain inspectable and backed up as unbound material.

`lib/readfield-controls.js/.css` contracts default chrome. N opens an annotation; R folds/unfolds review. Scope, WPM, voice, bookmarks, RIDE, source tools and RETURN remain behind explicit controls. A selected exact text span overrides current scope; otherwise ANNOTATE uses the native focused range.

Working conclusion + source-ordered notes export as Markdown. JSON backup/import binds to exact source revision, rejects forged offsets/quotes, preserves parked marks without promoting their authority, and merges under the existing 64-mark bound. No network service receives annotations.

## Acceptance / falsifiers

1. At 320/390/1280px, primary controls remain inside the viewport; no horizontal document overflow. Text remains legible and source tools reachable.
2. Set a purpose, select a passage, author an interpretation/question, save, fold, return to context and reload: source bytes and exact cursor survive. Edit, remove and undo retain note identity.
3. Searching regex punctuation, CJK and emoji returns original UTF-16 source offsets. Search is literal; bounded results disclose truncation.
4. Scrolling, seeking, RSVP and voice create no interpretation marks. Repeated/overlapping notes do not inflate annotated coverage.
5. Changed bytes at the same path contribute zero old coverage. Old notes remain inspectable; forged imports change nothing. Corrupt/blocked storage is explicit and does not overwrite existing evidence.
6. Existing READ ↔ STRUCT ↔ WRIST, native READ/RIDE/RETURN, timed-cue and legacy trail tests remain strict. The continuity smoke opens the now-explicit source-tools disclosure before choosing WRIST.
