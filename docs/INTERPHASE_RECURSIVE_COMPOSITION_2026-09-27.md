# INTERPHASE RECURSIVE COMPOSITION — 2026-09-27

Status: **WORKING METHOD / HANDOFF**, not a new runtime or ontology.

## Core move

The recurring technique across FIELD, FOLD//BLOOM, Sleeper, Verse, I Ching, J-space and the recovered INTERPHASE lineage is:

```text
ONE OBJECT
  → one stable ADDRESS
  → several UNEQUAL APERTURES
  → a few LAWFUL TRANSFORMS
  → WITNESS
  → RETURN
```

The important simplification is **recursive composition**:

> any aperture may itself resolve to another addressed object that exposes the same small grammar again.

That is the useful "fractal" property. The recursion is in the **contract**, not in forcing all domains into one shared content model.

```text
FIELD INDEX
  └─ object A
      ├─ READ aperture
      ├─ RIDE aperture
      ├─ MAP aperture
      └─ RETURN
           └─ object B
               ├─ STEP
               ├─ LENS
               └─ RETURN
```

A complicated system can therefore remain locally small. Each layer needs to know:
- what object it owns;
- how that object is addressed;
- what views are lawful;
- what transformations are actually supported;
- what authority each view has;
- how to return.

Do not solve complexity by adding one universal mega-state.

## Why this is different from a taxonomy

Bad convergence:

```text
I Ching = J-space = Fold/Bloom = Sleeper = Body = City
```

Working convergence:

```text
each may implement:
ADDRESS → APERTURE → TRANSFORM → WITNESS → RETURN
```

and may exchange a bounded artifact if the receiving host declares support.

Shared grammar, unequal state.

## FIELD LAB

FIELD LAB is best understood as a **composition bench**, not a destination application.

Its seven modes are deliberately unequal:

- RIDE — embodied native engine;
- PULSE — temporal/entrainment witness;
- VERSE — text/line/mark authoring projection;
- READ — addressed temporal reading;
- LOCI — route/memory projection;
- INK — material deposition simulation;
- DATA — addressed structural/change projection.

The useful LAB question is:

> can the same owned object survive projection through several apertures without losing source identity or laundering one projection into another's authority?

The mobile repair in the same branch makes LAB usable as this bench on a phone: one horizontal aperture strip, one bounded bottom sheet, measurable non-overlap/tappability.

Do not add an eighth LAB mode merely because another donor exists. A donor should first compose through an existing aperture or remain research.

## SLEEPER

Sleeper contributes a distinct and highly valuable primitive:

```text
WORLD
→ ROUTE
→ ENACTED GATES
→ TRACE
→ RETURN ARTIFACT
```

Its strongest convergence seam is **path as evidence**.

The City Engine / ASCII world should not become a transport app by default, but transportation is an excellent concrete reading because:

```text
travel = addressed traversal through a changing field
```

The same machinery can represent:
- walking/riding through an ASCII city;
- game navigation;
- poem traversal;
- agent/tool paths;
- replay ghosts;
- real transit traces;
- alternate same-world routes.

Useful transfer:

```text
route witness
= world/source identity
+ ordered addressed steps
+ locally observed state
+ human/agent marks
+ return address
```

This is compatible with STEP and ghost replay without making Sleeper subordinate to Fold/Bloom.

## I CHING / CORRESPONDENCE

Use the I Ching as a **finite ambiguity-preserving correspondence lens**.

The current 64-state binary surface is useful because it:
- is small enough to inspect completely;
- has explicit transforms;
- preserves structured ambiguity;
- gives stable addresses for change relations.

It is not a replacement for native control state. Native LIVE evidence already falsified the 64-state hex quotient as sufficient control state for next lawful forecasts.

A modern machine-facing correspondence should therefore look like:

```text
native object/state
  ↓ explicit projection Q
finite relation address
  ↓ structural transforms
candidate correspondences
  ↓
return to native evidence
```

Every correspondence should carry:
- projection rule;
- information lost;
- ambiguity remaining;
- transforms supported;
- claim boundary;
- return path.

This permits mapping into body, real-world gates, planning, city routes or model state without pretending the mapping is physically or causally complete.

## J-SPACE

```text
model state
→ readable disposition
→ explicit host mapping
→ lawful native candidate set
→ ambiguity
→ PREVIEW
```

It should never become universal state or silent execution authority.

In LIVE the current seam is:

```text
J-space hint
    ↓
forecastContext()
    ↓

```

This is a good example of recursive INTERPHASE composition:
- J-space owns model evidence;
- LIVE owns game state and action legality;
- FIELD PULSE transports a bounded hint;
- RETURN preserves what happened.

## TRON / FORTRESS DONOR

Do not copy the game skin.

The transferable mechanism is **trajectory modifies future affordance**.

From the supplied Fortress description:

```text
motion
→ trail / local topology
→ topology changes viable future motion
→ coupled speed / drafting / rubber margins
→ team role allocation emerges
```

Candidate transfers:

### 1. Path leaves a constraint field

For ASCII City / Sleeper:

```text
route is not only where you went;
route may alter what is easy, visible, blocked, expensive or attractive next
```

This could be ephemeral, replay-only, or explicitly authored. Do not mutate canonical city topology without a host law.

### 2. Simple local physics, deep global strategy

Prefer:
- 2–4 comprehensible local laws;
- coupled consequences;
- visible residue;
- repeated reuse;

over dozens of named mechanics.

This is directly relevant to LIVE and ASCII City.

### 3. Resource margin rather than health bar

"Rubber"-like recoverable margin is interesting as a donor:
- temporary tolerance near a boundary;
- regenerated through safe spacing/time;
- spent to survive a risky path;
- visible enough to learn.

Possible hosts: movement/route prototypes only. Do not inject into production Fold/Bloom without a missing function.

### 4. Cooperative topology

Fortress is especially relevant if ASCII City gains multiple ghosts/agents:
- one agent creates room;
- one occupies/defends;
- one probes a boundary;
- routes become cooperative structures.

This is a better research direction than generic NPCs.

## INDEX / FIELD INDEX RULE

The public index should increasingly behave like the same recursive composition grammar.

A route entry needs to answer, at minimum:

```text
WHAT IS THIS?
WHO OWNS ITS STATE?
WHAT CAN I DO HERE?
WHAT DOES IT OPEN INTO?
HOW DO I RETURN?
```

Do not expose every internal donor equally.

Recommended hierarchy:
1. primary usable object;
2. its current apertures/actions;
3. optional research/donor lineage;
4. RETURN.

FIELD INDEX should reduce apparent project count by showing **composition and parentage**, not by deleting provenance.

## APPLY THIS METHOD BEFORE ADDING A NEW SYSTEM

Ask:

1. What exact object is missing?
2. Does an existing host already own it?
3. Is the request actually a new aperture over an existing object?
4. Can an existing transform express it?
5. What information is lost?
6. What authority is required?
7. What is the RETURN?
8. Can the result recurse cleanly into another host?

If 1–7 cannot be answered, do not create a new route.

If they can, the implementation should usually be surprisingly small.

## Distillation

The technique is not "map everything to everything."

It is:

> **keep every object locally small, give it stable addresses and a few lawful apertures, compose those apertures recursively, preserve the residue, and always keep a way back.**
