FIELD / OPERATIONAL PROTOCOL · v0.1

SOURCE → HOLD → TURN → TRACE → RETURN

What exactly? → Hold one thing → Make one bounded move → Prove what changed → Write what came back. EFFECT inside TURN still requires an explicit host-native RELEASE/commit boundary.
SOURCEHOLDTURNTRACERETURN
USE: Point to the exact thing. Hold one focus and ≤3 lawful moves. Turn once. Trace actual consequence. Return evidence and stop. If a stage cannot exit cleanly, STOP and name the missing condition.

SOURCE

What exact thing are we acting on?
ENTRY
A request, signal, issue, object or returned residue exists. · No exact canonical object/focus is yet fixed for this move, OR a prior RETURN requires fresh replanning.
DO
Resolve the authoritative owner and exact address/version/ref. · Separate source facts from derived interpretation. · Record only the source refs needed to recover the object.
EXIT
Exactly one primary object/focus is named. · Owner + exact address/ref are known. · If authority/source cannot be resolved, exit STOP_UNKNOWN rather than guessing.
EXAMPLE
Stale architecture-map report → source /nexus/map.html at its current blob SHA; owner is 0xxx0/0xxx0.github.io; /control/CURRENT.json and showcase-manifest.json are supporting sources, not substitute authority.

HOLD

What are we holding constant while we act?
ENTRY
SOURCE exited with an exact object/focus and owner. · Inspection/read access for the intended move is lawful.
DO
Freeze object id/address, current focus, objective, constraints and RETURN address. · Expose 1–3 native moves maximum. · Name the stop rule and any required commit/release boundary.
EXIT
Object/focus can be re-identified after interruption. · The allowed move set and authority boundary are explicit. · RETURN address is known before action.
EXAMPLE
Hold the current system-map object; objective = make its architecture current; allowed moves = edit map, verify map, return evidence; stop if the current root/manifest authority disagrees.

TURN

What is the one bounded move?
ENTRY
HOLD is valid. · One supported native move has been selected. · Required permissions/constraints are satisfied.
DO
Preview declared consequence and reversibility when available. · Perform one bounded native operation only. · For VIEW/NAVIGATION/OFFER moves, TURN may complete directly. · For EFFECT moves, cross an explicit host-native RELEASE/commit boundary; the carrier/protocol itself never dispatches effects.
EXIT
The native operation was attempted once and produced a result handle, changed artifact, commit/ref, or explicit failure. · No unrelated second move was started. · If the move was unsupported or authority was absent, exit STOP_UNSUPPORTED.
EXAMPLE
Patch the existing architecture map and its exact navigation/manifest references as one bounded repo change set; do not use the same authority to start a second redesign.

TRACE

What actually happened?
ENTRY
TURN produced an attempted result or explicit failure.
DO
Run machine-verifiable checks first: syntax, invariant/unit tests, replay/fixtures, responsive/browser smoke, route/link checks, diff/roundtrip as applicable. · Record PASS, FAIL or INDETERMINATE per claim. · Separate repository/software proof from real-device, human, physical or social evidence.
EXIT
Every material claim has an evidence ref or is explicitly UNKNOWN/INDETERMINATE. · Observed consequence is distinguishable from forecast/intention. · Failure is preserved rather than rewritten as success.
EXAMPLE
Static parse confirms one HTML/SVG document and all 11 requested nodes; committed root link + manifest entry are re-read successfully; live browser rendering remains INDETERMINATE if no browser/CI run is available.

RETURN

What came back, and what is now reusable?
ENTRY
TRACE exists, including failures/unknowns.
DO
Write durable before → after delta, evidence refs, residue/lesson and unresolved unknowns. · Record the exact object/result identity needed for re-entry. · Release the held execution authority. · Set next = NONE unless a new SOURCE/HOLD cycle explicitly replans.
EXIT
A durable receipt or equivalent evidence object exists. · The loop is closed and resumable from source + evidence. · No next action is implied by completion alone.
EXAMPLE
Write /returns/SYSTEM_MAP_CONVERGENCE_2026-10-02.json with before/after/evidence/residue; then stop. Any further architecture work begins again at SOURCE.

CODING / AGENT HANDOFF

SOURCE  object_id · owner · address/ref · facts · unknowns
HOLD    focus · objective · constraints · ≤3 native moves · return address · stop rule
TURN    selected native move · authority · RELEASE gate if EFFECT · expected consequence · reversibility
TRACE   executed checks · PASS/FAIL/INDETERMINATE · evidence refs · unknowns
RETURN  before · after · delta · residue · evidence refs · unknowns · next: NONE
One loop carries one addressed object/focus. Projection changes do not create a new object.
At most three lawful native moves may be exposed while HOLD is active.
TURN means one bounded native move. If that move has EFFECT authority, an explicit host-native RELEASE/commit gate is required before dispatch.
TRACE records observation/evidence only; it never creates permission, priority, identity or authority.
RETURN closes the move. No second move inherits authority from the first.
PASS requires executed checks. Missing human/device/world evidence is INDETERMINATE/UNKNOWN, not PASS.
If a stage cannot satisfy its exit condition, STOP and name the missing condition. Do not forage for substitute work.
