## Recovered private sources

### Systematising Glyph Design for Visualization — exact Drive PDF
Chapter 7.2 is directly about poetry visualization.

Recovered source findings:
- close-reading variables span formal, phonetic, semantic and contextual information;
- investigators identified 33 variables, retaining 26 as useful;
- 52 poetry-analysis tasks were identified;
- not all variables are useful all the time: task classes need different subsets, so importance is task-dependent;
- poem-component glyphs represented words/punctuation and phonetic/semantic relations;
- macro-glyphs summarized line-level sound change / poem turbulence;
- static summaries were more useful for comparing lines; animation was useful for perceiving overall flow;
- PoemViewer integrated poem upload, visualization and rule-based mappings;
- unstable mappings and repeated legend lookup add cognitive load;
- glyphs need perceptual separability under small size / low contrast / greyscale.

Primary transfer: **QUESTION → SELECTIVE MAPPING**, not SHOW EVERYTHING.

## External quarry

### Rule-based Visual Mappings / PoemViewer
Transfer: stable poem + task/question-specific visual mappings + focus/context. Goal is flexibility without a giant control panel.

### Poemage / RhymeDesign
Transfer: sonic relations become navigable paths across poem space while text remains visible.
Boundary: sound relations require a real phonetic/language backend; spelling is not rhyme.

### Co-PoeTryMe / PoeTryMe
Transfer: language + form + seeds + surprise; select word/line; request constrained alternatives; bank possibilities; explicitly adopt/replace. PoeTryMe supports English as well as Portuguese/Spanish.

### iPoe
Transfer: poetic form can be a declarative contract rather than a separate app. Form rules may include line/stanza structure, syllables, rhyme and repeated lines; breaking rules should be explicit poetic license.

### Poetry Machines
Transfer: preserve unequal assist modes. Fourteen professional poets proposed widely different interactive machines tied to artistic practices/traditions; one universal assistant behavior is not the goal.

### PoemPalette (CHI 2026)
Transfer: poetic elements can become manipulable objects in a visual workspace while the poem remains editable; symbol selection/graphs/color-emotion views are optional projections.

### plotspaces (2026)
Transfer: a poem projection can become a physical/fabricated return. Boundary: physicalization is a reading/projection, not semantic proof.

# Forward route map

## R1 — WRITE / POSSIBILITY DOCK
Donors: Co-PoeTryMe + Market/Solver.
Experiment: select word/phrase/empty slot → intent → 3–7 candidates grouped by WHY → BANK / ADOPT / REJECT / LOCK.
Stop: generic autocomplete or silent replacement.

## R2 — FORM / CONSTRAINT GRAMMAR
Donors: iPoe + PoeTryMe + Verse Atlas evidence contracts.
Experiment: declarative form adapter: stanzas, lines, syllables/chars, rhyme groups, repeated lines, soft/hard constraint, license cost.
Stop: each form requires rewriting core poem state.

## R3 — SOUND / SONIC TOPOLOGY
Donors: Poemage + PoemViewer.
Experiment: real phonetic adapter with rhyme/alliteration/assonance/consonance sets projected over visible poem.
Stop: spelling substitutes for phonetics or map hides source.

## R4 — MAP / SELECTIVE VISUALIZATION
Donors: Maguire thesis + Rule-based Visual Mappings + PoemViewer.
Experiment: **POEM MAP 0.1** — one visible poem + one selected question/lens + click focus + static line comparison.
Stop: legend lookup becomes a burden or named task is not clearer than text.

## R5 — GAME / CONSTRAINT PUZZLE
Donors: Grid Path + JUE/JU game + Market/Solver.
Experiment: lock anchors + form/semantic/path constraints + require two lawful solutions + author chooses.
Stop: game score improves while poem worsens.

## R6 — STUDY / EVIDENCE
Donor: Verse Atlas.
Experiment: same poem state → source / derived / editorial / open study lens.
Stop: metadata mutates poem or interpretation masquerades as validation.

## R7 — CORPUS / DISTANT-CLOSE BRIDGE
Experiment: select phrase → tiny ranked corpus/style/form neighborhood with provenance + reason.
Stop: corpus volume itself becomes the interface.

## R8 — MATERIAL / PHYSICAL POEM
Donors: plotspaces + glyph/fold/fan lineage.
Experiment: one poem + one declared relation → SVG/print/fold object with recoverable text.
Stop: decorative-only physicalization.

## R9 — PERFORMANCE / TEMPORAL READING
Donors: RSVP + Pathweaver score + ONE LAW/TWO SENSES + macro-glyph work.
Experiment: same poem → RSVP / spoken-boundary / static line summary and compare tasks.
Stop: animation harms comparison without answering a new question.

## R10 — CROSS-LANGUAGE / TRANSFER
Donors: PoeTryMe multilingual + Grid Path EN/ZH/MS/TA + Jueju.
Experiment: same authoring operation across English and Chinese while language metrics stay separate.
Stop: one language’s prosody/grammar is projected onto another as equivalence.
