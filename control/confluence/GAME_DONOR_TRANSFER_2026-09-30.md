# GAME DONOR TRANSFER — FIELD

**State:** bounded donor map, not a game-design layer.

The six games are admitted only as mechanism donors:

- **Outer Wilds → knowledge-gap residue:** UNKNOWN ≠ TASK. This is already live as held-object `MORE HERE`.
- **Hades → attempt continuity:** attempt end ≠ continuity reset; failed/aborted work may leave one addressed RESIDUE without minting NEXT.
- **Death Stranding → asynchronous infrastructure:** repeated helpful passage may earn a reusable edge/adaptor candidate without synchronous coordination.
- **Into the Breach → forecast before commit:** expose declared effect/authority/target/reversibility before the move. This pass makes it executable.
- **Hardspace: Shipbreaker → salvage before subtraction:** destructive cleanup must name KEEP / CUT / DEPENDENTS / HAZARDS / RETURN.
- **Terra Nil → scaffold retirement:** when capability survives independently, remove the enabling scaffold instead of canonizing it.

Machine-readable mapping: `/control/GAME_DONOR_TRANSFERS.json`.

## Cross-donor synthesis

```
GAP        → what is not yet known?
ATTEMPT    → what survives failure?
TRACE      → what repeated passage deserves infrastructure?
FORECAST   → what happens if I commit?
SALVAGE    → what must survive subtraction?
RETIRE     → what can disappear once capability survives?
```

These are six different answers to one FIELD problem: **how can consequence accumulate without accumulating unnecessary control structure?**

The donor order is intentionally asymmetric. Outer Wilds is already proved in current FIELD. Into the Breach is implemented next because it sharpens an existing action surface. The remaining four stay candidates until a concrete current friction calls them forward.
