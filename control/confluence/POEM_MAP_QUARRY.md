## Recovered / external visualization donors

### PoemViewer / Oxford poetry visualization
Rule-based visual mappings visualize phonetic articulation and poetic structure.
The later macro-glyph work was motivated by overload at low-level glyph detail and introduced line-level summaries for comparison.

Transfer:
- do not overlay every analytic variable directly on the poem
- support semantic zoom: token → line summary → poem
- line/macro-glyph summaries can become an optional overview layer

### Poemage
Strong donor.

Three linked entrances:
- SET view
- POEM view
- PATH view

Its key move is not "draw a network." It keeps abstract sonic topology tied to the original poem while allowing multiple entrances and playful manipulation.

Transfer:
- PAGE / MAP / SETS in Poem Map
- relationship sets create paths through poemspace
- original source remains readable and addressable
- map is useful when it reveals interaction among patterns, not just statistics

### Myopia
Close-reading visualization with multiple encoded poetic dimensions.

Transfer:
- analysis layers should be optional lenses, not permanently visible clutter
- source fidelity matters
- comparison/deformation can reveal structure without replacing reading

### COPE

- live formal/prosodic feedback
- rhyme dictionaries

Transfer:

- candidate inspiration can come from real corpus neighborhoods

## AXIAL analogy

AXIAL improved when "interesting interface shape" became:
**stable semantic state × continuous transform × explicit aperture × transaction/RETURN**.

The analogous Verse move is:

```
POEM STATE
× RELATION LAW WEIGHTS
× APERTURE
× AUTHOR SELECTION / PATH
→ POEM MAP PROJECTION
→ CANDIDATE / CONSTRAINT ACTION
→ RETURN
```

This is materially different from a static visualization.

## Information-overload law

Do not decorate source text with all discovered features.

Use:
- source remains plain enough to read
- selection determines fovea
- APERTURE progressively reveals peripheral relations
- PAGE / MAP / SETS are linked but unequal
- detailed evidence appears on demand
- line/macro-glyph overview may summarize only after token-level analysis becomes too dense

## Forward routes

### ROUTE A — CANDIDATE DOCK (highest authoring value)
Selection → intent verb → provider candidates → compare 2–4 → BANK / ADOPT / REJECT.

Intent verbs:
CONTINUE / REPLACE / ECHO / CONTRAST / TURN / RHYME / COMPRESS / EXPAND / SURPRISE / BREAK.

Candidate provenance is mandatory.

### ROUTE B — DECLARATIVE FORM ENGINE
Extract current form objects into data:
line counts / syllable targets / rhyme graph / repeated-line constraints / meter validator hook / language hook.

Then add forms without app forks.

### ROUTE C — LINE GLYPHS / POEM TURBULENCE
Mine Oxford macro-glyph work.
Build optional line-level summaries to reduce token-level overload.
Do not make them mandatory.

### ROUTE D — CORPUS NEIGHBORHOOD
Selected line or current poem → corpus neighbors.
Start with exact local/user corpora; add embeddings/provider only behind explicit adapter.
This is COPE / ReRites scale.

### ROUTE E — GAME / CHALLENGE
Constraint challenge is a real authoring state:
preserve locked words + satisfy declared form/relation goal + produce ≥2 legal solutions.
No separate score-only artifact; solved game state remains editable poem state.

### ROUTE F — VISUAL / SYMBOL
Poem elements → user-chosen visual symbols / paths / glyphs.
PoemPalette donor.
Keep source↔symbol provenance explicit.

### ROUTE G — LEARNING / MOTHER
Use MOTHER only to test whether a projection helps:
PAGE vs MAP
MAP vs SETS
full field vs APERTURE
blocked vs interleaved candidate search
Not part of normal authoring UI.

## Kill conditions

Kill any route if:
- plain text beats it at its named job
- it expands cognitive load without improving discovery/choice
- it destroys source traceability
- it claims semantics from geometry alone
- it requires a separate app merely because language/form changed

### POEM MAP 0.2 — co-creative authoring descendant
Route: `/poetry/map/`

Adds:
- linked PAGE / MAP / SETS entrances;
- typed ORDER / SOUND / REPEAT / AUTHOR relations;
- continuous relation weights;
- APERTURE for visual load;
- locks and explicit author paths;
- candidate bank;
- non-destructive TRY preview;
- explicit ADOPT gate;
- revision ancestry + undo;
- form adapters + RETURN.

The 0.2 claim is not that a graph writes poetry. The map earns its existence only when it shortens a real authoring decision while preserving source identity and a plain-text return path.
