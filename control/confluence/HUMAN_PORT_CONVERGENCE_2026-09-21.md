# HUMAN PORT / CONVERGENCE PASS — 2026-09-21

Status: **CURRENT SYNTHESIS / IMPLEMENTED SURFACE CANDIDATE**

This document treats the HUMAN PORT conversation as one evolving object rather than a sequence of feature requests.

## 1. Repeated user intent recovered

Across the thread, the user repeatedly pushed toward the same deeper object from different angles.

### ADDRESS
- one generic public entry that works for a random person / business-card encounter
- bespoke share links for known people, projects or situations
- stable identity/address even when channels change
- artifacts/tools/context may be bundled into a shareable encounter
- slash/path projections are useful, but should not become separate sovereign apps

### INTERPRET
- human language is polysemous and context-sensitive
- high-entropy / recursive / interrupted owner speech must be treated as first-class input
- preserve raw wording; do not silently normalize into one clean interpretation
- distinguish OBSERVED / POSSIBLE / UNRESOLVED
- interpretation may support other languages, register/decorum, rehearsal and study
- consequential ambiguity requires readback/confirmation

### RELATE
- relation, culture, time, phase, communication capacity and situation can change the correct projection
- familiarity/frequency does not create authority
- private causes should remain private; public projections may expose only coarse consequences
- family/friend/work/agent are unequal projections over the same underlying person/address

### HARVEST
- preserve funny/weird exchanges that actually changed an artifact
- recover useful mechanisms from conversations without publishing raw chat
- offers, ideas, promises, follow-ups and questions may leave useful residue
- residue does not automatically become a task or moral debt
- helping another person (for example a cousin with an app idea) should preserve both the human offer and the idea lineage without conflating them
- App Foundry / Idea Atlas is the natural destination for durable app/tool ideas

### CONTINUITY / RETURN
- communication should preserve what actually happened
- unfinished promises may be DONE / VALUE_TAKEN / RELEASED / DEFERRED / HANDOFF / SUPERSEDED
- silence alone must not imply danger, incapacity or death
- continuity under reduced capacity may require trusted-human handoff
- reversible action before irreversible action
- the system should prove useful now, not only describe future automation

## 2. Current architectural decision

HUMAN PORT is broader than communications.

Canonical model:

```
OUTSIDE
  ↓
ADDRESS / PORT
  ↓
INTERPRET
  ↓
POLICY / AUTHORITY
  ↓
TRANSFORM / EXPRESSION
  ↓
RETURN
```

Core law:

**CONTACT != INTERPRETATION != AUTHORITY != ACTIVATION.**

A person/message/agent/artifact may bind to the port without automatically causing action.

## 6. Current gaps — real, not speculative

1. **Private person/relation/channel registry**
   - no operational private registry yet
   - no automated harvest should be claimed until actual ingestion/provenance exists

2. **Real inbound transport**
   - public GitHub Pages remains static
   - Telegram adapter exists as a mechanism, not a finished private ingress

3. **Outbound authority**
   - human share/copy is live
   - agent/bot sending requires explicit policy and disclosed automation
   - DRAFT != SEND remains default

4. **Capsule lifecycle/security**
   - fragment capsules are bearer-visible, not secret
   - expiry/revocation/private opaque capsule IDs remain future work if real usage demands them

5. **Social residue runtime**
   - contract exists
   - automatic extraction/queue should begin read-only and be proven on a tiny real fixture

6. **Idea Atlas completeness**
   - historical App Atlas source is recovered
   - current public Idea Atlas is only a core seed + local capture
   - full lineage import should happen only if it improves actual navigation

## 9. Success criterion

HUMAN PORT is working when an interaction can produce useful value without forcing the user to:
- remember every promise
- turn every idea into a project
- expose private context
- explain their whole system to another person
- let an agent over-act
- rediscover why an artifact exists

The desired result is:

**SMALL PUBLIC APERTURE · LARGE RECOVERABLE DEPTH · NARROW AUTHORITY · USEFUL RETURN.**
