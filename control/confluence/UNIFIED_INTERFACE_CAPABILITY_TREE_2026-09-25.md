# UNIFIED INTERFACE CAPABILITY TREE — 2026-09-25

Status: cross-lineage capability projection. Authority: NONE.

Parent law: `/control/confluence/UNIFIED_INSTRUMENT_PIVOT_2026-09-25.md`.

This map does not create a new app, state store, scheduler, router or ontology. It describes what the human can lawfully do while holding one addressed object across six current hosts.

## READING LAW

Every host is rendered through the same minimal frame:

```
HELD OBJECT
→ REACHABLE MOVE(S)
→ WITNESS
→ RETURN
```

A route is implementation depth, not the primary human unit.

Capability state vocabulary:

- **AVAILABLE** — current implementation exposes the move.
- **PROVED** — repository/runtime evidence establishes the mechanism; lived value may still be unproved.
- **CANDIDATE** — implemented on an open current branch but not yet merged.
- **WAITING** — blocked on human/world/lived evidence or a deliberately unimplemented seam.
- **FORBIDDEN** — authority boundary; another host owns the mutation.

## GLOBAL TREE

```
                           ┌──────────────────────────────┐
                           │ HELD OBJECT / FOCUS FRAME    │
                           │ id · address · authority     │
                           │ projection · return_to       │
                           └──────────────┬───────────────┘
                                          │
             ┌──────────────┬─────────────┼─────────────┬──────────────┬──────────────┐
             │              │             │             │              │              │
          DAYLINE       FOLD//BLOOM     COMMS         HOUSE         SHOPPING        VERSE
             │              │             │             │              │              │
       execute in time   transform /    resolve       orient /       resolve        author /
                         experience      obligation    trace context  acquisition    revise text
             │              │             │             │              │              │
             └─────── bounded addressed handoffs / exact RETURN paths ────────────────┘
                                          │
                                  WITNESS / RETURN
                                          │
                              same object or native owner
```

The graph is intentionally not symmetric. Dayline may schedule or enact a sourced obligation, but it cannot silently mutate the native truth owned by COMMS, HOUSE, SHOPPING, VERSE or FOLD//BLOOM.

## 1 / ATLAS DAYLINE

Current merged head: **FIELD LIVE 0.2.1 / REALITY PORTS / MOBILE ACTION**.

### HELD OBJECT

One local DayState focus:

- a native Dayline task;
- an explicitly imported FIELD candidate;
- an explicit HOUSE context envelope;
- an explicit SHOPPING next-action envelope;
- an explicit COMMS OPEN-signal envelope.

Identity includes task id plus source provenance when imported. Dayline owns temporal execution state, not source-domain truth.

### REACHABLE MOVES

**AVAILABLE / PROVED BY SOURCE**

1. **FOCUS / APPLY / ADD** — explicitly accept an incoming object into today's local DayState.
2. **RUN ≤ 3 / ACT** — select a bounded executable route and act within current time/context constraints.
3. **RETURN / COPY HANDOFF** — emit local execution evidence and a bounded authority-NONE continuation packet.

Secondary projections remain available:

- PLAIN action list;
- ATLAS;
- SCENARIO;
- LIVE FIELD intake.

They are views/supporting controls, not separate object identities.

### WITNESS

- selected task and route;
- current time/context;
- source class + provenance;
- local event/evidence tape;
- RETURN checksum/state;
- explicit feedback/handoff packet.

The witness proves what Dayline changed locally. It does not prove that the source host accepted the outcome.

### RETURN POINT

- native Dayline state/replay when the task originated locally;
- exact `return_to` / source reference when the task arrived from HOUSE, SHOPPING or COMMS;
- copied worker packet for external continuation, authority NONE.

**WAITING:** Dayline RETURN → native-source receipt OFFER → source explicit ACCEPT/REJECT. This is the next hard seam and is not yet generalized.

**FORBIDDEN:** automatic COMMS coverage, Shopping lifecycle promotion, HOUSE state/actuation, Verse adoption, FOLD source/map mutation.

## 2 / FOLD//BLOOM

Current product law: `SOURCE → ADDRESS → MAP → PROJECTION → OPERATION → TRACE → RETURN`.

Current merged family includes LISTEN, LIVE, READFIELD handoffs, LOCI, PULSE, SET, TWO DIAL, REPLAY, VOICE, INK and LAB 0.2.2. FIELD LAB 0.3 VERSE work is a current **CANDIDATE** in PR #260.

### HELD OBJECT

One exact source identity plus current address/focus:

- audio source;
- text source;
- ordered set;
- current interval / beat / phrase / section / text span;
- authored marks where present.

The source never becomes its waveform, terrain, scene, mnemonic course, replay score or brush trace.

### REACHABLE MOVES

Local neighborhood depends on source/evidence.

**SOURCE / no map yet**
1. **MAP / CARTOGRAPH** — derive inspectable structure in LISTEN or canonical text addressing in READFIELD.
2. **READ / PLAY SOURCE** — use the source without pretending derived terrain exists.
3. **RETURN** — leave with source identity intact.

**MAPPED / addressed**
1. **MARK** — BOOKMARK / FLAG / ARC as authored evidence.
2. **RIDE / EMBODY** — LIVE over the same source/map.
3. **REPLAY / COMPOSE** — author an expressive score or borrow bounded timing into composition.

**TEXT focus**
1. **READ** — canonical cursor/RSVP.
2. **LOCI** — spatial mnemonic projection over exact spans.
3. **VERSE** — candidate PR #260: carry exact source/focus/human marks toward Poem Map or REPLAY.

### WITNESS

- exact source id/hash/reference;
- AUDIO MAP / text address;
- BEAT / PHRASE / SECTION evidence;
- BOOKMARK / FLAG / ARC packet;
- EVENT TAPE;
- LIVE authored operation trace;
- REPLAY JSON score;
- LOCI addressed course;
- bounded HIT/GRAZE/MISS trace where Saber is used.

Presentation profile is never source truth.

### RETURN POINT

Always returns to the exact source identity plus enough addressed evidence to inspect/replay the transformation.

Native authorities remain unequal:

- LISTEN → source/map/marks;
- READFIELD → text cursor;
- LIVE → ride/deformation trace;
- REPLAY → expressive score;
- SET → ordered seams;
- Poem Map → verse revision, when handed off.

**WAITING:** lived coherence/reuse; two-real-phone Saber proof; PR #260 lived VERSE chain.

## CROSS-HOST CAPABILITY EDGES

These edges are the actual unified interface.

```
COMMS addressed OPEN signal
    └── ADD TO DAY ──> DAYLINE sourced task
                          └── ACT / RETURN
                                └── WAITING: receipt OFFER back to COMMS

HOUSE selected address
    └── APPLY CONTEXT ──> DAYLINE context
                              └── ACT / RETURN
                                    └── RETURN_TO HOUSE address

SHOPPING capability gap / next_action
    └── ADD TO DAY ──> DAYLINE sourced task
                          └── ACT / RETURN
                                └── WAITING: receipt OFFER back to SHOPPING

FOLD//BLOOM exact source
    ├── MAP ──> MARK ──> RIDE / REPLAY
    └── TEXT focus ──> READ ──> LOCI
                         └── candidate VERSE handoff ──> POEM MAP

VERSE exact source/focus
    ├── TRY ──> ADOPT ──> revision witness
    ├── READ / LOCI via candidate LAB bridge
    └── REPLAY via source-scoped marked moment
```

The absent edge is deliberate and important:

```
DAYLINE RETURN
    -X-> source state mutation

DAYLINE RETURN
    --> source-addressed RECEIPT OFFER
    --> native source ACCEPT / REJECT
```

The first arrow is forbidden. The second is the next convergence seam.

## MINIMAL UNIFIED HUMAN FRAME

The tree suggests one reusable visible carrier, not a shell:

```
[ OBJECT ]
exact title / id
address · owner · projection

[ FOCUS ]
current clause / room / item / task / source interval / token

[ NEXT ]
1. highest lawful move
2. alternate
3. RETURN

[ WITNESS ]
what just changed
what remains unproved

[ RETURN ]
native owner / exact address
```

Host-native interfaces remain free to be radial, spatial, textual, temporal or game-like. Only these semantics need continuity.

## WHAT SHOULD BE VISIBLE BY DEFAULT

### Dayline
Focus + next executable action + RETURN. Projection controls recede.

### FOLD//BLOOM
Source + address + one context-dependent transform. Deep family routes recede.

### Comms
Current addressed obligation + response state + Dayline only when time is the missing resource.

### House
Current spatial address + projection/trace/context. No false device control.

### Shopping
Current capability gap + gate + next unresolved action. Listings are evidence, not identity.

### Verse
Current source/focus + contextual authoring move + source-change witness. MAP/SETS/constraints remain depth.

## PROPAGATION ORDER

1. **DAYLINE proof first** — one sourced object enters, acts, RETURNs, and preserves exact source address on phone.
2. **RETURN OFFER seam** — implement one native-source receipt acceptance proof, preferably SHOPPING or COMMS, without universalizing it.
3. **FOLD/VERSE continuity** — if PR #260 passes lived use, show source/focus + local next operations instead of a mode-navigation wall.
4. Only then consider rendering the larger capability graph as an optional Atlas/tech-tree projection.

## STOP CONDITIONS

Do not:
- expose every capability at once;
- turn this document into a second CURRENT;
- assign shared authority to the carrier;
- replace host-specific witness types with one generic event model;
- convert every route into a permanent button;
- infer that a handoff means the receiving host accepted the source-domain consequence.
