# UNIFIED INSTRUMENT PIVOT — 2026-09-25

Status: convergence constraint + propagation guide. Not a new app, store, dashboard, queue, or authority.

## TRIGGER

Direct user evidence: recent Atlas Dayline / reality-port work is useful, but the collaboration still feels like separate fields and buttons. The model is converging faster than the gesture.

The issue is not lack of interoperability. HOUSE, SHOPPING, COMMS and DAYLINE now have bounded handoffs. FIELD, READFIELD, Scale Lens, LISTEN and INTERPHASE already preserve identity, address and authority across projections.

The remaining gap is felt continuity.

## CORE DISTINCTION

Integration asks whether one host can hand an addressed object to another host without corrupting authority.

A unified instrument asks whether the human can keep hold of the same object/focus, see the next lawful move, act, witness the change, and RETURN without mentally reconstructing which app or page owns the next step.

Therefore:

UNIFIED INTERFACE = continuity of OBJECT + FOCUS + OPERATION + WITNESS + RETURN, not identical chrome and not co-location of all data.

Routes remain implementation addresses. They should become secondary in ordinary use.

No new core is required to express this pivot.

## THE SMALLEST SHARED HUMAN SURFACE

At any moment, an adapted host should be able to expose one compact frame:

CURRENT OBJECT
address / authority / projection

FOCUS
what part is held now

NEXT
one to three lawful operations reachable from this state

WITNESS
what changed / what remains unproved

RETURN
exact re-entry + provenance

This may be rendered differently by each host. The invariant is semantic and operational, not visual sameness.

A full page may still exist. A radial atlas may still exist. A poem map may still exist. HOUSE may still be spatial. They become projections entered from a persistent focus, rather than destinations the human must remember and navigate between.

## TECH TREE REINTERPRETATION

The useful tech-tree idea is not a tree of projects or pages.

It is a local capability graph around the current object.

Node:
- a capability or lawful operation, not an app.

Edge:
- a prerequisite or evidence condition that makes the operation reachable.

State:
- AVAILABLE — callable now.
- ACTIVE — currently being enacted.
- PROVED — returned with evidence.
- WAITING — depends on human/world input.
- RESIDUE — known but not carried by this projection.

Examples:

TEXT SOURCE:
READ → MARK → COMPOSE → REPLAY
MARK → LOCI

OPEN MESSAGE SIGNAL:
ADDRESS → DAYLINE → ACT → RETURN OFFER → SOURCE ACCEPT/REJECT

HOUSE ADDRESS:
SELECT → CONTEXT → DAYLINE
SELECT → NATIVE HOUSE OPERATION, only when HOUSE authority permits

The primary UI should show only the local neighborhood, usually one to three forward operations, not a giant global graph. The larger graph is an optional atlas/projection for orientation and recovery.

This converts forward progress from navigation into state change:

MOVE → WITNESS → RETURN → newly reachable MOVE.

## IMMEDIATE PROPAGATION RULES

### ATLAS DAYLINE

The mobile repair in PR #258 is directionally correct because it makes action precede the full atlas.

Next refinement should reduce the feeling of a toolbar of destinations:

- keep one visible current focus/task;
- show RUN or the next lawful move before projection controls;
- move ATLAS / PLAIN / SCENARIO / LIVE choices behind projection/context disclosure when they are not needed;
- incoming HOUSE / SHOPPING / COMMS envelopes should appear as changes to the current focus, not as another subsystem panel;
- RETURN should visibly close the loop and expose what became reachable next.

Do not make Dayline the universal shell.

### FOLD//BLOOM / VERSE / LAB

PR #260 is directionally correct because exact text + focus + marks survive VERSE → READ / LOCI / Poem Map / REPLAY.

Propagate the same interface law:

- source identity/focus remains persistent;
- modes are projections/operations, not separate destinations;
- the current source should expose only reachable next operations;
- marks are evidence attached to the source, not a reason to create another mark manager;
- Poem Map retains authoring authority; REPLAY retains score authority.

Do not flatten unequal modes into one generic workspace.

### FIELD INDEX / ROOT

FIELD should increasingly answer:

1. what object/focus is current?
2. what changed?
3. what one to three operations are reachable now?
4. what is waiting on reality?
5. where does RETURN land?

Routes/manifests remain discoverable depth, not the primary cognitive burden.

The existing glyph/address grammar is a good compression carrier. It should point into capability/action continuity rather than merely more route navigation.

### HOUSE / SHOPPING / COMMS

Do not import their full UIs into Dayline or FIELD.

Each host should expose:
- exact current address;
- one bounded handoff or native operation;
- authority boundary;
- RETURN target.

The unified feeling comes from carrying focus and verbs across the seam, not from embedding every host in one page.

## PROGRESS TEST

A cross-host change is a genuine interface advance only if a user can take one real object through this loop with less reconstruction:

OBJECT → FOCUS → NEXT OPERATION → CHANGED OBJECT/WORLD → WITNESS → RETURN

Pass when:
- exact identity/address survives;
- the next move is visible without scanning a project menu;
- no hidden authority transfer occurs;
- BACK/RETURN restores the expected focus;
- the user can tell what changed and what became possible next.

Fail when:
- a new button merely opens another subsystem;
- the user must remember which page owns the next step;
- the same object is copied into another canonical state;
- progress is only a receipt, route, or metadata update.

## SMALL FIRST PROOF

Do not rebuild the site.

Use one existing object and one existing seam:

FIELD current object
→ one persistent focus frame
→ Dayline RUN
→ RETURN
→ same frame now shows the next reachable operation

If this meaningfully reduces control hunting on phone, propagate the carrier to one FOLD//BLOOM text/audio loop. If it does not, keep the underlying handoff architecture and discard the shared visible carrier.

## CONVERGENCE STATEMENT

Yesterday's pivot was: one durable object, unequal projections, bounded transformations, explicit authority, recoverable history.

Today's correction is the human-facing consequence:

one held object, one visible focus, few reachable moves, visible consequence, exact RETURN.

That is the interface to propagate.
