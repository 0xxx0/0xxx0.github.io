# HOUSE / MARKS

**Status:** CONFLUENCE DONOR / CANDIDATE TRANSPLANT  
**Source:** ChatGPT House OS glyph-and-spatial-marking thread, culminating in `HOUSE_OS_FIELD_SYSTEM_v1.1_A3.pdf` / `HOUSE_OS_FIELD_SYSTEM_v1.1.zip` (2026-09-17).  
**Repo status of source bytes:** not yet ingested; this packet preserves the transfer contract, not the exact binary artifact.

## One line

**Test whether physical marks can expose identity, state, relation, permissible action and return paths across real surfaces while remaining useful when every digital enhancement disappears.**

This is not a new HOUSE subsystem. It is a bounded interface/projection donor for HOUSE / SPATIAL, FIELD INDEX and related physical workflows.

## Why it survives the newer architecture

The original field pack explored:

- glyph topology
- color coding
- spatial position
- typography and viewing distance
- folds / occlusion
- removable mounts and cassette edges
- light as dynamic state
- printed IDs, QR/NFC/fiducial correspondence
- physical ↔ digital reconciliation
- progressive enhancement / graceful degradation
- legibility and function tests
- buy / wait gates

The newer control architecture supplies the stronger substrate:

`WORLD → SENSE → ADDRESS → STATE → TRANSFORM → PROJECT → ACT → MEASURE → RETURN`

and the identity law:

**IDENTITY ≠ LOCATION ≠ PROJECTION ADDRESS.**

So the pack is best understood as a **MARK projection / physical interface test harness**, not as an independent registry or ontology.

## Hard corrections

1. **The pack's `HOS-###` machine IDs are local test-fixture IDs, not canonical HOUSE/FIELD identities.**  
   When a real object already has a stable FI/HOUSE ID, print/project that identity instead of minting another one.

2. **`entity_registry.csv` is a worksheet/projection, not source of truth.**  
   FIELD INDEX / HOUSE owns durable identity and ports; CONTINUITY may own ongoing case context; marks only expose a bounded view.

3. **Location never substitutes for identity.**  
   A mark may encode or point to an address, frame, parent or projection address, but moving the object does not create a new object.

4. **O / M / I / P are visual evidence annotations, not a replacement for provenance.**  
   They may mean Observed / Measured / Inferred / Proposed inside a mark grammar; the underlying receipt still carries evidence/source.

5. **QR / NFC / AprilTag / CV markers are pointers and adapters.**  
   They should resolve identity or an action surface; mutable truth remains in the owning substrate.

6. **Color must earn semantic bandwidth.**  
   Orange/blue may be retained as sparse channels only when ablation shows faster recovery, fewer errors or a distinct useful variable.

7. **Reference frame is mandatory when position carries syntax.**  
   Declare object-relative / viewer-relative / room-relative before LEFT / RIGHT / TOP / BOTTOM acquires meaning.

8. **Light adds a variable; it never becomes the baseline language.**  
   Printed/manual interpretation survives power, network and controller loss.

9. **A fold or occlusion may transform visibility, not silently mutate identity.**

10. **Do not create a parallel shopping system.**  
    Material/electronics procurement returns through the FIELD capability pipeline: NEED → QUERY → FOUND → VERIFY → WATCH → DECIDE → BUY → RECEIVE → TEST → ADOPT.

## Transfer units

### 1. MARK projection

A reversible physical projection attached to an already-addressed target.

Candidate shape:

```yaml
mark_id: local mark instance
target_id: canonical HOUSE/FIELD identity
projection: MARK
frame: object|viewer|room|surface
carrier: paper|tape|vinyl|paint-test|fold|light|screen|other
encodes:
  - identity
  - state
  - relation
  - permissible_action
  - return_path
evidence_annotation: O|M|I|P|none
state_snapshot_ref: optional pointer, never authority by itself
reversibility: full|partial|none
expires: optional
return: receipt/address
```

This is a **candidate record**, not a promoted schema.

### 2. Interface Tile

The strongest reusable artifact from the thread is the small physical **Interface Tile**:

```
GLYPH / ID
TYPE / STATE
EVIDENCE
NEXT / PORT
machine-readable pointer
```

Current interpretation:

- human-readable first
- canonical target ID rather than duplicate identity
- optional pointer to FI/HOUSE/CONTINUITY state
- removable carrier
- state can be stale and must never pretend otherwise
- useful even with QR/NFC/light/network removed

### 3. Legibility / function harness

A mark earns adoption by changing behavior, not by looking coherent.

Default experimental measures:

- wrong-but-plausible reading
- recognition / action latency
- viewing distance
- reference-frame error
- recovery after interruption
- recovery after move / re-parent
- stale-state detection
- orientation error
- successful return-to-home / return-to-state
- PLAIN ↔ FIELD ablation

Thresholds from the original pack (for example 90% recognition or <5 s recovery) remain **experiment defaults**, not universal laws.

### 4. Progressive-enhancement ladder

```
L0  physical identity / passive mark
L1  handwritten or movable state
L2  phone-readable pointer / digital projection
L3  sensed or illuminated state
L4  automation / actuation intent
```

Failure of L4 must not erase L0-L1.  
No higher layer gains HOUSE runtime authority merely because it is convenient.

### 5. Transforming carriers

Folds, sliding layers, removable cassettes and lighting remain useful because they expose transformation directly:

- fold = visibility/state transform
- edge strip = mating/orientation/interface projection
- occlusion = explicit partial visibility / unknown remainder
- light = optional temporal or active-state channel
- removable mount = reversible placement / rapid ablation

These mechanisms can transfer into ENV-0, partition/cassette, cart, robot/sensor, tool-return and service/cat zones without merging those lineages.

## Relation to current systems

### HOUSE / SPATIAL

Primary recipient.

MARK reads from:

- HOUSE_1 spatial addresses / surfaces
- HOUSE_2 observation/state/event layer

MARK may project:

- identity
- state
- relation
- route
- warning / forbidden state
- next permissible action
- evidence annotation

MARK does **not** become Home Assistant authority. An actionable mark emits an intent or pointer; HOUSE_3 / HA still authorizes actuation.

### TRACE

TRACE and MARK are adjacent but unequal.

- TRACE = authored/observed ordered path over addressed substrate; temporal recurrence and replay matter.
- MARK = persistent or temporary physical projection at a target/surface; local legibility and action matter.

A TRACE may produce MARKs. A MARK may point into a TRACE. Neither collapses into the other.

### FIELD INDEX

FIELD INDEX supplies durable identity, capability, I/O, ports, dependencies and exit paths.

MARK must not mint a competing registry.  
A successful physical test may instead add or update the relevant FI object's physical ports / evidence / return path.

### CONTINUITY / CASE

CONTINUITY handles recurring human/animal/house/device/project cases and source/claim/gap history.

MARK can project a tiny, privacy-safe operational state from a case. It does not duplicate the case ledger.

### FOUNDRY

This thread contributes directly to **SYMBOL ↔ OPERATOR** and **IMAGE ↔ MATERIAL**:

- symbol becomes a tested physical operator
- visual composition becomes a reversible material intervention
- consequence returns as measured legibility / action / error

## First recipient-side proof

Do not print the full 43-page pack.

Use four unlike real carriers:

1. one **tool**
2. its **home/storage location**
3. one **removable panel/cassette**
4. one **mobile node** (phone/cart/sensor module)

For each:

- use existing canonical ID if available
- add one reversible MARK
- declare reference frame
- encode no more than identity + one useful state/action
- run at least one normal interaction and one interruption/reorientation
- record wrong reading, hesitation, stale state, orientation failure and RETURN
- compare against PLAIN label/no-mark control where practical

**Promotion gate:** only after a real bounded RETURN demonstrates lower ambiguity, faster recovery, safer action or better state correspondence should MARK become a first-class HOUSE projection.

## Procurement rule

The original pack's materials list remains quarry only.

Buy only when a tested gap names the capability:

- removable marking material — if paper/tape test proves recurring value
- reusable attachment — if carrier movement/re-parenting matters
- transparent overlay — if layered/occlusion grammar proves useful
- NFC / fiducial — if machine lookup beats printed ID alone
- addressable light — only if dynamic state earns a variable passive marks cannot carry

No purchase is promoted directly from visual enthusiasm.
