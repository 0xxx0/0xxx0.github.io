## DESIGN LAW

### 1. SUBSTANCE GENERATES FORM
Do not begin with cards, settings pages, dashboards or hero typography.

Begin with:

```
OBJECT
→ ADDRESS
→ RELATIONS
→ OPERATORS
→ CONSEQUENCE
→ RETURN
```

Then derive geometry, controls, typography and animation from those relations.

### 2. EDGE IS A FIRST-CLASS PLACE
A relation may carry:
- transform;
- gain;
- uncertainty;
- timing;
- constraint;
- provenance;
- seam;
- permission.

Do not force every operation into a node/card/sidebar if its natural address is the connection.

### 3. FEWER INPUTS, DEEPER CONTEXT
Prefer one gesture / dial / path whose meaning is constrained and inspectable over many unrelated controls.

Examples already in our lineage:
- radial selection;
- fold / bloom polarity;
- path traversal;
- aperture scale;
- source-time scrub;
- drag-to-steer + branch choice;
- pressure/speed/tilt as brush state.

### 4. SPATIAL MEMORY IS FUNCTION
A user should be able to remember **where** something lives.

Stable relative position is evidence. Re-layout should be deliberate.

### 5. UI MAY RECEDE
When the source/world is legible, chrome should disappear.

Use:
- peripheral witnesses;
- contextual apertures;
- temporary toolglass;
- local labels;
- event-driven surfacing.

Do not make every capability permanently visible.

### 6. TYPOGRAPHY IS SIGNAL, NOT ARCHITECTURE
Large editorial typography is valid for a doorway, manifesto, or deliberate pacing event.

It is not a substitute for operational structure.

Inside instruments:
- type should indicate state, address, scale, action or consequence;
- giant headings should not consume the work surface;
- forms should feel like instruments / consoles / sheets / fields, not marketing documents.

### 7. PRIMITIVE-FIRST IMPLEMENTATION
Prefer:
- HTML;
- Canvas / SVG;
- CSS;
- Web Audio;
- small ES modules;
- deterministic local state;
- explicit JSON packets;
- browser-native pointer / keyboard APIs.

Add dependencies only when they buy a hard missing capability.

Reason:
- keeps causal model inspectable;
- permits code-golf / demoscene-like density;
- makes composition and reuse cheap;
- reduces framework-shaped aesthetics;
- preserves local/offline control.

### 8. AESTHETIC VECTOR ≠ HOUSE STYLE
Nous/Hermes, Septabee, MIT Media Lab, demoscene, thi.ng, Lindong, Xem, print/editorial, sumi/ink, square-kufic, games and physical instruments are **donors**, not one mandatory skin.

HOUSE code should instead preserve a small set of formal invariants:
- hard geometry;
- exact alignment;
- dense but quiet state;
- purposeful motion;
- explicit hierarchy;
- low decorative radius;
- meaningful spatial persistence;
- material / causal feedback;
- typography subordinate to operation on working surfaces.

### 9. DELIGHT MUST HAVE A CAUSE
A surprising visual, sound, motion, haptic or transformation should reveal:
- an event;
- a relation;
- a successful operation;
- a scale transition;
- a hidden structure;
- a recovered state.

Delight without a cause becomes wallpaper.

### 10. QUALITY BAR
Target research-demo quality where:
- the mechanism is novel/useful enough to deserve explanation;
- the interaction can be learned by touching it;
- the visual form makes the mechanism more legible;
- implementation is small enough to inspect;
- failure / uncertainty remains visible;
- the artifact produces a durable RETURN.

“MIT Media Lab or better” means rigor of concept + prototype + presentation + evaluation, not imitation of institutional aesthetics.

## APPLICATION PRIORITY

### FOLD//BLOOM
Immediate:
1. reusable wet-media / brush engine;
2. explicit experience profile with few macro controls and optional deep tuning;
3. shareable zero-file demo URLs;
4. drop / anticipation choreography driven by source evidence;
5. source/event/path continuity between RIDE / PULSE / READ / LOCI / INK / DATA;
6. edge-operators on event tape / paths where transformations naturally belong.

### FIELD INDEX
For forms / operational surfaces:
- migrate away from generic web-form appearance;
- make source/address/state legible first;
- compact labels into instrument rails;
- use spatial groupings that persist;
- reveal advanced controls through aperture, not permanent form sprawl;
- retain accessibility and native input semantics.

Do not redesign the entire index in one pass. Create one shared primitive and migrate high-use forms as bounded transforms.

### HOUSE / PHYSICAL
Treat physical interfaces as the natural extension:
- light / sound / airflow / motion as peripheral state;
- compression rails / partitions / rotary surfaces as graspable address spaces;
- sensors and actuators should publish the same source→state→operation→return semantics.

## CURRENT IMPLEMENTATION GATE

A proposed design change should answer all seven:

1. What exact object is manipulated?
2. What address remains stable?
3. What relation does the geometry expose?
4. What operation is actually available?
5. What sensory change witnesses consequence?
6. What is source evidence vs profile/preference?
7. How does the user RETURN / undo / replay / inspect?

If those are unanswered, styling work is premature.
