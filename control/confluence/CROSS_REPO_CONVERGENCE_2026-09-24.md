## Convergence thresholds

Do not use a single “convergence score.” Require gates.

### G0 — IDENTITY
The same object remains exactly identifiable across repos/views/transforms.

**PASS:** exact stable id/hash/address survives.
**FAIL:** copies become competing identities.

### G1 — RETURN
A projection or transformation has a durable route back to source/current authority.

**PASS:** source + state + residue + return address are reconstructable.
**FAIL:** useful output strands context.

### G2 — COMMUTATION
Where two surfaces claim equivalent operation, operating through either surface yields equivalent canonical state.

```
HOST --op--> HOST'
 |             |
project       project
 |             |
VIEW --op--> VIEW'
```

**PASS:** equality/equivalence is proved for named operations.
**FAIL:** hidden synchronization or divergent semantics.

### G3 — SOVEREIGNTY REDUCTION
Convergence must not create another canonical store.

**PASS:** shared mechanism moves downward; domain truth stays with owner.
**FAIL:** a new shell/database is introduced just to synchronize old shells.

### G4 — SURFACE COMPRESSION
Depth may increase only if visible sovereignty/re-entry burden does not.

**PASS:** at least one duplicate destination, control, explanation, or lookup path is demoted/removed/absorbed.
**FAIL:** capability rises only by adding another peer surface.

### G5 — RE-ENTRY
A fresh worker can recover the current head without reconstructing the chat forest.

**Target:** current question -> authority map -> exact head/evidence in <=3 bounded reads.
Measure failures, not prose volume.

### G6 — CONVERSION
Repository movement must become usable capability or external consequence.

A delta counts as progress only if it causes one or more of:

- new usable operation;
- exact recovery that unlocks one;
- user-facing simplification;
- another-human/world/device/physical consequence;
- measurable reduction in uncertainty or re-entry cost that directly unlocks the above.

Receipts, branch counts and seals alone do not count.

### G7 — LIVED VALUE
For creative/experiential instruments, technical equivalence is insufficient.

**PASS:** ordinary use produces a clear retained value signal: orientation, agency, comprehension, delight, memorable consequence, or useful changed state.
**FAIL:** machinery is impressive only when explained by project lore.

## Progress vector

Record progress as a delta vector, not a scalar:

```
ΔCAPABILITY
ΔRECOVERABILITY
ΔSURFACE_BURDEN
ΔUNCERTAINTY
ΔEXTERNAL_CONSEQUENCE
ΔLIVED_VALUE
```

A move is net-positive when at least one desired axis materially improves and no protected invariant regresses without an explicit trade.

### Strong progress
usable capability + evidence + lower re-entry/surface burden + real contact/RETURN.

### Weak progress
code/tests/receipt that remove a blocker but do not yet convert.

### Non-progress
new coordination object, branch, score, summary, seal or architecture with no changed capability/uncertainty/consequence.
