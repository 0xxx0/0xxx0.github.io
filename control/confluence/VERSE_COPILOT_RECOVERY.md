# VERSE / CO-CREATIVE POETRY — RECOVERY + REPLAN

Status: corrective reorientation
Date: 2026-09-21

## What regressed

The 2026-09-21 "CHINESE POETRY COPILOT" reconnection recovered real Jueju lineage but over-promoted one adapter into the product identity.

That caused several regressions:

1. The user entered a preselected Chinese seven-character draft rather than a possibility space.
2. The interface became a form editor before it became a co-creative instrument.
3. Pathweaver's source→path→reading→glyph/score play, Grid Path's SOURCE→DRAW→BY→PATH→VIEWS→RETURN loop, and Market+Solver's candidate/bag/constraint machinery were demoted to donor links.
4. "English Jue Ju = NOT IMPLEMENTED" was technically accurate but product-misleading: it treated languages/forms as separate products instead of adapters over a common authoring loop.
5. The UI offered little answer to the central authoring question: "I have a feeling/word/fragment; what can I do next without asking the machine to write the poem for me?"

## Product law

**One co-creative poetry instrument. Language and poetic form are orthogonal adapters.**

Do not create:
Chinese Poetry App
English Poetry App
Malay Poetry App
Jueju App
Free Verse App

Create:

```
VERSE
  POEM STATE
  ├─ LANGUAGE ADAPTER
  ├─ FORM ADAPTER
  ├─ ASSIST / CANDIDATE PROVIDERS
  └─ PROJECTIONS / GAMES / STUDY
```

### POEM STATE
Preserve:
- current text
- selection
- locked spans
- candidate bank
- adopted/rejected candidates
- constraints
- revision ancestry
- provenance
- projections
- return receipt

### LANGUAGE ADAPTER
May supply:
- tokenization
- dictionary / definitions
- rhyme resources
- syllable/stress/tone information
- morphology
- corpus neighbors
- semantic relations

No language adapter owns the product.

### FORM ADAPTER
May supply:
- number of lines
- target lengths
- syllable/character counts
- rhyme scheme
- caesura
- repetition
- parallelism
- permitted path/grid topology
- evidence obligations

Examples:
- JUEJU / 5- or 7-character
- CUSTOM FOUR-LINE
- FREE VERSE
- CELL/PATH
- SONNET-like constraints (future)
- EN JUEJU TRANSFER EXPERIMENT: explicitly state what is preserved/lost; do not claim historical equivalence

### ASSIST / CANDIDATE PROVIDER
Given a selected span + declared constraints, emit optional candidates.

Candidate sources may include:
- local/source vocabulary
- dictionary relations
- rhyme/sound neighborhood
- corpus neighbors
- path/search discoveries
- language model suggestions
- human-entered bank

Every candidate records WHY it appeared.

The system never silently inserts a candidate.

### VIEW / GAME / STUDY
The same poem may project as:
- PAGE
- LINE
- GRID/PATH
- CANDIDATE BANK
- GLYPH
- SCORE/SOUND
- RSVP
- STUDY/EVIDENCE
- GAME/CHALLENGE

A projection is not a new poem unless the author commits it.

## Actual authoring loop

1. START
   - blank
   - seed words
   - fragment
   - import existing poem
   - choose example/form only if desired

2. SELECT
   - word
   - phrase
   - line
   - empty slot
   - path/cell

3. DECLARE INTENT
   Compact moves:
   - CONTINUE
   - REPLACE
   - SHARPEN
   - SURPRISE
   - RHYME
   - ECHO
   - CONTRAST
   - TURN
   - COMPRESS
   - EXPAND
   - BREAK RULE

4. CONSTRAIN
   Only relevant constraints appear.
   Examples: syllables, rhyme, line length, tone, polarity, semantic relation, path rule.

5. EXPAND POSSIBILITY
   Emit several candidates grouped by difference, not one "answer":
   SAFE / SIDEWAYS / WILD is a possible display model.

6. REDUCE OVERWHELM
   - lock what is already right
   - candidate bank remembers alternatives
   - active constraints explain rejection
   - compare 2–4 candidates at a time
   - progressively reveal deeper controls

7. ADOPT / KEEP / REJECT / BANK
   Author decides.

8. PROJECT / PLAY
   Optional path, grid, glyph, sound, RSVP, challenge.

9. RETURN
   Save exact poem + ancestry + constraints + chosen candidates.

## Game layer

The game is not "guess what the AI wants."

A challenge declares a compositional problem:
- preserve these locked words
- reach this rhyme/syllable pattern
- make L3 turn without reusing a key word
- connect selected semantic anchors through a legal path
- satisfy form with minimum edits
- create two lawful solutions and choose

The writer solves it by selecting/moving language.

Success yields a poem state that remains editable and personally authored.

This is where Foundry's path laws / least-change solver / route receipts become directly useful to ordinary poetry-making.

## Immediate correction

The /poetry/ page should stop calling the whole product "Chinese Poetry Copilot".

Rename/reorient it as VERSE / co-creative poetry.

Keep Jueju visible as a strong adapter and keep the canonical unresolved opener recoverable, but do not preload it as everybody's starting state.

The next functional implementation should be **selection → contextual candidate dock → locks/constraints → candidate bank**, because this is the point where the product begins helping a person choose words rather than merely displaying a form.
