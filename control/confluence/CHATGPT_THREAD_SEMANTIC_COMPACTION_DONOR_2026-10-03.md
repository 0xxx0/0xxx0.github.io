> preserve rich human expression upstream; formalize downstream; keep raw evidence recoverable; compile only the smallest task-specific state needed to act.

## 2. Human-compliance law

The operator should not have to become a prompt engineer to use the system.

A worker may receive incomplete, associative, self-correcting natural language and internally resolve the **smallest sufficient task contract**:

```text
OBJECTIVE
DELIVERABLE
RELEVANT CONTEXT
CONSTRAINTS
SUCCESS / EVIDENCE
UNCERTAINTY
METHOD
```

The worker should expose this scaffold only when it materially changes a decision or repairs ambiguity.

Adaptive depth:

```text
L0 DIRECT  — obvious / cheap / reversible → answer or act directly
L1 COMPILE — multi-part / analytical / artifact work → internal task contract
L2 DEEP    — costly / archival / code / multi-source → recover → compile → execute → verify → return
```

Escalate only when complexity or consequence warrants it.

**Human fast path:**

```text
say the thing naturally
  → system finds the object/frame
  → system proposes/does ≤3 lawful moves
  → human intervenes only at real PING / CHOOSE / WORLD_RETURN gates
```

This is compatible with Crew Seam's `KEEP / PARK / WRONG_FRAME` steering and human-gate law.

Failure condition: the operator must manually maintain the compiler state, repeatedly re-brief workers, or translate ordinary intent into machine syntax.

## 3. Semantic compaction law

Do not compress a corpus into one universal summary.

Use layered representations:

```text
L0 RAW SOURCE
   exact conversation / file / artifact; immutable provenance

L1 EPISODE PACKET
   what changed here? decisions / failures / artifacts / open loops

L2 SEMANTIC REGISTER
   deduplicated atomic knowledge independent of conversation order

L3 RELATIONAL GRAPH
   provenance / dependency / contradiction / derivation links

L4 WORKING PACKET
   smallest task-conditioned subset needed now

L5 PROJECTION
   UI / DataDisc / glyph / cards / visual map
```

Higher layers index or transform lower layers; they do not delete or silently replace them.

**Compress upward; retrieve downward.**

Task-conditioned preservation matters. A coding packet may prioritize current state/constraints/tests; a fiction recovery packet may prioritize exact wording/voice/provenance/variants.

## 4. What every useful compaction should preserve

Use this compact loss test:

```text
CORE   governing state / model
DELTA  what changed
EDGE   rare but high-information material
BREAK  contradiction / correction / falsifier
MISS   known missing evidence / unresolved source
```

Why: frequency is not the same as information value. Corrections, contradictions, anomalies, failures and one-off fragments can be more valuable than repeated consensus.

Round-trip test:

> If only the compact representation survived, could another worker recover the important objective, constraints, decisions + rationale, contradictions, artifacts, open gates, and source pointers?

If not, repair the packet before further compression.

## 5. Claim / research trajectory

Where provenance matters, preserve the trajectory rather than only the final prose:

```text
SOURCE
  → OBSERVATION
  → CLAIM
  → MODEL / INTERPRETATION
  → IMPLICATION
  → DECISION
  → ARTIFACT / ACTION
  → TEST / OUTCOME
  → UPDATE
```

Not every chain requires every node.

Later evidence should challenge/supersede a claim without rewriting the earlier source.

Useful distinctions:

```text
ORIGIN ≠ ADOPTION ≠ CURRENT CANON
OBSERVED ≠ DERIVED ≠ HYPOTHESIS
SHIPPED ≠ USED ≠ PROPAGATED ≠ COUNTERMEASURE
REPETITION ≠ INDEPENDENT CORROBORATION
```

## 6. Retrieval before prompt-fencing

The long thread produced several elaborate single-thread analysis prompts. Their durable lesson is **not** to run them over every conversation.

Preferred flow:

```text
archive / FTS / source index
   → retrieve likely high-value material
   → apply the narrow transformation needed
   → write canonical artifact / RETURN
```

Use deep excavation only for sources with high expected uniqueness, provenance value, cross-link value or artifact potential.

Do not replace mechanical retrieval with giant prompts.

## 7. Useful transformation operators

These are operators, not new subsystems.

### CRYSTALLIZE
Selected evidence → smallest non-redundant set of decision-useful propositions. Preserve disagreements and citations.

### VALUE / POSSIBILITY
Assume the ordinary summary is known. Extract:

```text
★ unique signal
∴ implication / why it matters
→ practical use / integration
◇ non-obvious possibility
△ cheapest verification
A artifact that should exist
```

Monetization is one optional value-realization lens, not the default objective.

### ARTIFACT COMPILE
Work backward from a target artifact:

```text
requirements
constraints
principles
components
relationships
failure modes
missing information
→ evidence-to-design translation
→ build spec
```

### AUDIT
Ask whether the source set itself should be culled, split, consolidated, complemented or tested. Do not confuse generated derivatives with independent evidence.

### DELTA ONLY
When prior summary is already known, return only material that is new, surprising, qualifying, contradictory, action-changing or uniquely evidenced.

### HANDOFF
Return terse atomic state, not an essay:

```text
K knowledge
R requirement
D decision
F failure
Q question
V verify
A artifact
X cross-link
```

## 8. Recovery / archaeology operators

For Prison Age, Sleeper, aphorisms, scripted responses and other historical creative material:

1. **recover before inventing**;
2. distinguish primary source from later reconstruction;
3. preserve variant genealogy rather than smoothing contradiction;
4. preserve minor/funny/abandoned fragments when they have generative value;
5. distinguish canon, experimental branch, later instrument, rejected/superseded material and missing material;
6. generate new work only after historical layers are explicitly separated.

Useful provenance distinctions:

```text
USER-ATTESTED
ASSISTANT-ATTESTED
JOINTLY DERIVED
EXTERNAL / ADAPTED
RECONSTRUCTED
UNRESOLVED
```

Do not claim global novelty merely because a phrase appears corpus-original.

## 9. Glyph / DataDisc / visual-system law

The thread's strongest visual-system conclusion is architectural, not aesthetic:

```text
RAW EVIDENCE BELOW
SEMANTIC / RELATIONAL SUBSTRATE IN THE MIDDLE
TASK-SPECIFIC / BEAUTIFUL PROJECTIONS ABOVE
```

The projection must never become the source of truth.

Separate:

```text
semantic id
operator / relation
state
unicode fallback
custom glyph
renderer / layout
```

Meaning is not identical to a Unicode character or a rendered glyph.

A visual transform earns its place only when it exposes a useful structure (topology, causality, uncertainty, sequence, hierarchy, comparison, action aperture) rather than repeating the same summary decoratively.

## 10. Prompt / agent placement

Do not install the whole theory into every system prompt.

Global worker invariant should stay small:

```text
infer intent from natural language
recover/inspect before inventing
use the smallest sufficient context
execute rather than merely explain
label uncertainty / provenance
verify consequential claims
return evidence + residue + exact re-entry
```

Detailed procedures belong in scoped skills/project instructions and should load only when the task requires them.

Do not run an extra prompt-rewrite model on every message unless measured benefit justifies its token/latency/distortion cost.

## 11. Thread-derived failure register

Do not repeat these patterns:

- turning every insight into another framework or ontology;
- replacing an actionable request with meta-commentary about the request;
- decorative metrics without a defensible method;
- global word-frequency analysis where phase/topic-conditioned analysis is more meaningful;
- treating psychological/intensity labels as measurements without operational definitions;
- over-compressing away voice, provenance, disagreement or anomalies;
- letting generated summaries/podcasts count as independent corroboration of their own source;
- using a beautiful graph/glyph map as authority;
- requiring the human to operate the orchestration machinery manually;
- analysing every archived thread equally instead of triaging retrieval by expected value;
- creating another surface when an existing host already owns the function.

## 12. Integration / test — no new dashboard

Use existing Crew Seam and `SOURCE → HOLD → TURN → TRACE → RETURN` on one real task.

Experiment:

1. operator gives an ordinary messy natural-language request;
2. worker internally compiles objective/deliverable/constraints/success;
3. worker resolves the existing host and exposes at most three lawful moves;
4. operator is asked only when the human gate is actually PING / CHOOSE / WORLD_RETURN;
5. worker returns evidence + residue + exact re-entry;
6. compare against an ordinary unstructured chat handoff.

Measure only useful outcomes:

- repeated briefing required;
- operator clarification burden;
- wrong-frame corrections;
- time-to-first-useful-action;
- number of unnecessary human interruptions;
- ability of a second worker to continue from the bounded packet without the full transcript.

Keep this donor only insofar as it reduces those costs.

## One-line contract

**Human language in; smallest truthful working state out; one bounded move; evidence back; source remains recoverable.**
