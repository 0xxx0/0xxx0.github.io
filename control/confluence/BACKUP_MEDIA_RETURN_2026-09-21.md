## Images and stories: a path, not another product

The private recovered backup contains **2,437 image files**. The public 13-image Site selection is intentionally much smaller. It must not be described as complete media recovery or a public backup of the image collection.

A private metadata-first candidate pass found 1,037 distinct image hashes associated with creative/project threads: 290 story/Sleeper candidates, 542 visual-language candidates and 205 field/research candidates. **These are retrieval candidates, not publication approvals.** Branch copies were hash-collapsed for review only; originals remain untouched. Review sheets and source links remain private. Some visual-language studies are boxed historical work, not active direction.

Use the existing ingest front, not a new gallery empire:

1. Select one current artifact or question; recover its images, app and design document together. A conversation title finds candidates but does not establish identity, ownership or public safety.
2. Preserve an exact original hash. Classify screenshot, generated concept, authored diagram, physical photo and runnable artifact separately. Review private information and third-party material before public copying.
3. Collapse only exact duplicate payloads. Keep distinct revisions and their differences. Similar appearance is not byte identity or an established version chain.
4. Publish a small coherent family with source authority and a return route. Keep account metadata, private chat IDs/URLs, prompts, personal photos and raw transcripts out.
5. If public payload volume becomes large, decide durable binary storage explicitly. Do not quietly substitute thumbnails for an original-file backup. The 1,037-candidate review set is about 2.37 GB, so it is not appropriate to push it blindly into this static-site tree.

### A small useful distinction

**Image = source object. Story = authored sequence of objects. Dayline = intended action in time. Return = observed residue.**

These can share a source ID without pretending to be one type. A missing image date stays unknown. A three-image story is not a historical timeline, completed work, or proof that an Atlas adapter exists.

The public story export uses `0xxx0/media-story-pack/v0.1`, keeps selected order and SHA-256/source-commit references, and explicitly declares `atlas_dayline_adapter: NOT_IMPLEMENTED`. It is a bounded handoff for examination, not an import promise.
