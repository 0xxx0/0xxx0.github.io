# CONFLUENCE

Confluence is a coordination shelf for unequal lineages. It is not a universal ontology and it is not another current-head product.

## Working law

**Coordinate through explicit preserved relations, source links, differences, and return paths. Do not collapse vocabularies merely because two projects rhyme.**

## Thread / worker model

Treat chat threads and external agents as **context-local workers**.

They may have different working context, temporary hypotheses, and tool access. They are not assumed to share live scratch state.

Durable shared coordination lives in:

- `/control/CURRENT.json` — cold-start orientation / current heads / recovery targets
- `/showcase-manifest.json` — FIELD INDEX tracked public surfaces and touch metadata
- `/control/MIGRATION.json` — recover/import/quarantine work
- `/control/CENSUS.json` — artifact census
- `/returns/` — evidence / receipts
- this confluence shelf — bounded cross-lineage handoffs that should remain readable

The existing FIELD INDEX (FI) law remains authoritative:

> DISCUSSION ≠ INDEX TOUCH; MUTATION → INDEX TOUCH.

Here **FI means FIELD INDEX**, not FIELD INTAKE. FIELD INTAKE remains the separate sovereign admission membrane for typed canonical records; ordinary repo/chat mutations must not bypass its review/APPLY boundary.

A thread can think for hours without changing shared durable state. If it commits a tracked public surface, it must perform the corresponding FIELD INDEX touch. If the mutation changes a current head, transfers a mechanism across lineages, or would materially reduce future re-entry cost, also leave a bounded Confluence packet and/or RETURN. Do **not** log every conversational turn: capture durable deltas, evidence, corrections and open gates.


## Collaboration corpus

The collaboration history itself is a recoverable source field: chats, user asks, generated images, code/artifacts, physical experiments, research and failed branches.

It is **not** a competing canonical runtime.

Use it to recover lineage and intent, then reconcile against current evidence.

Five standing rules:

1. **Chat history is source material, not present-state authority.** Current repo/live evidence wins when they disagree.
2. **Recover lineage, not project titles.** Preserve transformations, donors, rejected branches and current heads rather than treating every named chat/artifact as sovereign.
3. **Downstream agents receive bounded packets.** A useful handoff carries objective, current head, donor only if needed, delta, authority, acceptance test and RETURN.
4. **Large archive / small active surface.** Recovery may grow indefinitely; cognitively live fronts stay bounded by `CURRENT` / `QUEUE`.
5. **RETURN closes route authority.** After one bounded move, re-read returned state and explicitly replan. A suggested next route is evidence for attention, not permission for autoplay.

When mining prior conversations, user messages deserve special attention because asks, corrections, constraints and unfinished transformations are often embedded inside digressions. Recover what the user was trying to make happen, then verify what actually happened.

## Agent roles

- **Hermes** — default read-only recovery / research / ambient operator unless explicit write authority is granted.
- **ChatGPT** — cross-thread retrieval, synthesis, steering, and context packets.
- **Codex / repo writer** — bounded implementation after a target and write scope are explicit.
- **Repository** — durable executable/public state.
- **RETURN** — evidence / ground truth.

This means a broad research charter may be handed to Hermes safely only when the role header below remains in force:

```
MODE = READ_ONLY_RESEARCH
NO repo writes
NO file moves/deletes
NO external actions
NO autonomous messaging
Implementation clauses become candidate patches/specifications only.
Return a bounded handoff packet with sources, deltas, uncertainties, and next executable actions.
```
