Status: **PARKED / REOPENABLE DONOR**

## Why this packet exists

A research thread began with Quest 2 / open hardware and widened into robotics, local appliance control, motion tooling, physical addressing, instruments, cassette/furnisher systems and evidence logging.

The useful residue is **not another project**. It is a frontier packet for the existing HOUSE + AXIAL heads.

## Recovered convergence

Do not prematurely split these into sovereign projects:

- plotter / drawing robot
- rotary/indexing mechanism
- seal-carving machine
- interchangeable tool cassette
- robot arm
- physical instrument actuator
- spatial/XR control surface
- household device adapter

A useful shared reading is:

```text
INTENT / SOURCE
→ GEOMETRY / SIGNAL
→ PLAN
→ MOTION / TOOL / ADAPTER
→ WORLD
→ SENSE / MEASURE
→ EVIDENCE
→ RETURN
```

This is a **transfer grammar**, not evidence that every embodiment should share one controller or runtime.

## Strong donors

### Valetudo
Contribution: local-first device abstraction; capability/state interface instead of vendor-cloud UI imitation.

Transfer target: HOUSE runtime/adapters.

### Jubilee + FluidNC / grblHAL
Contribution: reusable motion substrate, explicit machine geometry, interchangeable tools, controller/runtime separation.

Transfer target: AXIAL physical builds, plotter/rotary/seal/instrument machinery.

### LeRobot / SO-101, AR4, OpenArm
Contribution: unequal manipulation routes:
- low-cost teleoperation/data/policy work;
- deterministic articulated manipulation;
- higher-capability reproducible physical-AI cell.

Transfer target: only after HOUSE/AXIAL names an operation that fixed-axis motion cannot satisfy.

### AprilTag
Contribution: disposable machine-readable identity/pose projection.

Constraint: tag is a coordinate/lens, never authority, lineage, permission or canonical identity.

### MCAP / Rerun
Contribution: timestamped embodied evidence / synchronized sensor-state replay.

Transfer target: RETURN / physical experiment receipts when ordinary files stop being sufficient.

### Faust
Contribution: signal/DSP specification separated from deployment target.

Transfer target: browser-first → embedded instrument/audio experiments.

### OpenStructures
Contribution: reversible interoperable physical interfaces and replaceable modules.

Transfer target: cassette/furnisher/partition/tool-dock work without forcing one geometry onto the whole house.

## Quest position

Quest 2 remains a valid **projection/input experiment**, not a primary machine-vision authority.

Reopen QUEST-SURFACE only to answer a concrete question such as:

> Does spatial presentation/control expose a HOUSE operation better than phone/desktop?

Do not build a native XR branch merely because the hardware exists.

## Robot-arm position

Do not choose an arm by category enthusiasm.

First name the missing operation, then compare:

```text
fixed-axis / motion deck
vs
articulated arm
vs
human + jig
```

The smallest embodiment that closes the operation and returns evidence wins the trial.

## Re-entry triggers

Reopen this packet when at least one is true:

1. a real fabrication/manipulation operation cannot be performed with current tools/jigs;
2. HOUSE needs a new sensing/addressing embodiment to close a current loop;
3. AXIAL needs physical machinery to test a named transform;
4. a current instrument/seal/plotter task has exact geometry + proof criteria;
5. a new open project materially replaces a brittle current subsystem.

## Stop conditions

Do not:

- create a new public core;
- buy a robot arm before naming its first operation;
- treat Quest as a machine-vision source without verified access;
- convert AprilTag labels into authority;
- force one motion/runtime stack onto every physical machine;
- let frontier research displace reality-gated HOUSE work.

## RETURN

This packet succeeds when a future thread can recover the frontier, name one missing capability in a current head, import only the required donor mechanism, run a bounded physical test, and return evidence without reopening the entire research branch.
