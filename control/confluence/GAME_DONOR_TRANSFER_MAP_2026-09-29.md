# GAME DONOR → FIELD TRANSFER MAP — 2026-09-29

**Status:** bounded research + transfer map.  
**Law:** steal mechanisms, not skins.

The purpose is not to make FIELD look like a videogame. A donor is admitted only when its mechanism solves an existing FIELD problem, the non-transfer residue is named, and the receiving host keeps authority.

## ADOPTED / ALREADY PRESENT

### Outer Wilds — knowledge can be progression
The game was deliberately designed around curiosity-driven exploration rather than explicit mission direction; its time loop strips away most material progress so knowledge becomes the durable gain.

**FIELD transfer:** unresolved knowledge may remain a question/gap rather than becoming a task. FIELD / CATCH + ACT already projects route-owned questions/open gaps as recoverable knowledge gaps; it does not promote them into obligations.

Sources:
- https://www.gdcvault.com/play/1027368/Independent-Games-Summit-Sparking-Curiosity
- https://www.gamedeveloper.com/design/live-die-repeat-how-i-outer-wilds-i-piques-curiosity-in-an-ambivalent-solar-system

**Residue:** time-loop fiction, ship log presentation and game content do not transfer.

### Into the Breach — show consequence before commitment
Subset's postmortem describes telegraphed enemy attacks, no hit/miss chance and deterministic resolution during the player's turn.

**FIELD transfer:** preview/navigation must remain distinct from commit/release. Current FOLD//BLOOM LIVE direct-choice work already lets forecast geometry seek/navigate while RELEASE remains separate authority.

Sources:
- https://media.gdcvault.com/gdc2019/presentations/Into%20the%20Breach%20Postmortem%20Final.pdf
- https://www.gamedeveloper.com/game-platforms/road-to-the-igf-subset-games-i-into-the-breach-i-

**Residue:** grid combat, damage economy and deterministic-game assumptions do not transfer to uncertain real-world domains.

### Death Stranding — traces can become infrastructure
Kojima Productions describes the Social Strand System as leaving useful traces/structures for other players; repeated contributions can improve traversability without synchronous co-presence.

**FIELD transfer already present:** BODY/FIT explicitly uses preparation → action → RETURN / PATINA. Git/RETURN evidence also functions as asynchronous trace rather than chat synchronization.

Sources:
- https://kojimaproductions.jp/index.php/en/death-stranding-directors-cut-beginners-guide
- https://www.kojimaproductions.jp/en/deathstranding2-SupportRookiePorters

**Held extension:** derive route-local/desire-path infrastructure only if repeated real traversal evidence can be obtained without another tracking burden.

## SHIPPED IN THIS CUT

### Hardspace: Shipbreaker × Terra Nil — safe subtraction
Shipbreaker makes dismantling depend on understanding a ship's interconnected systems and hazards before cutting. Terra Nil makes restoration culminate in a living landscape rather than permanent construction machinery.

**FIELD transfer:**

`SURVEY → ISOLATE → SALVAGE → CUT → VERIFY → RETURN`

Implemented as a read-only FIELD salvage audit:
- CURRENT/head evidence blocks retirement;
- children and compatibility aliases block retirement;
- runtime/tooling references block an explicit retirement candidate;
- frozen donors are preserved rather than mislabeled debt;
- aliases are preserved unless compatibility is explicitly migrated;
- candidate/parked/experiment surfaces enter SALVAGE_REVIEW;
- only an already-explicit SUPERSEDED / DEPRECATED / RETIRED / REMOVED surface can become RETIRE_CANDIDATE;
- the tool never auto-deletes.

Sources:
- https://www.blackbirdinteractive.com/shipbreaker
- https://www.terranil.com/

This is the first game-derived mechanism in this pass that adds a genuinely missing function: **convergence can now inspect subtraction safely instead of only accumulating or merging.**

## HELD DONORS — NO NEW SURFACE

### Hades — failure should return something
Supergiant describes a world whose characters remember the player across repeated attempts; narrative discovery continues through the death/restart cycle.

Potential FIELD invariant: a failed run may still return evidence, relationship state or residue, so failure != zero progress.

Source:
- https://www.supergiantgames.com/blog/hades-faq/
- https://www.gamedeveloper.com/design/how-supergiant-weaves-narrative-rewards-into-i-hades-i-cycle-of-perpetual-death

**Current fit:** packet RESIDUE / RETURN already carries much of this function. Do not add a failure-XP system unless a missing function appears.

### Baba Is You — rules can be inspectable objects
The game's rules exist as manipulable objects in the world and re-evaluate when rule text changes.

Potential FIELD invariant: rules/constraints should be addressable, inspectable and versioned rather than hidden conditionals.

Source:
- https://www.hempuli.com/baba/

**Current fit:** CODE//CITY, Law Zoo, FIELD contracts and constraint surfaces already cover much of this. Do not create a root rule editor.

## CROSS-DONOR TEST

A game mechanism transfers only if:

1. **FIELD friction exists first.**
2. **The abstract invariant can be stated without the game's fiction/UI.**
3. **A current host already owns the relevant truth and authority.**
4. **The mechanism reduces re-entry, ambiguity, unsafe action, bloat or distance-to-consequence.**
5. **Non-transfer residue is explicit.**
6. **The implementation can self-verify before asking the human to test it.**
7. **RETURN records whether the transfer survived contact with the unequal domain.**

## CURRENT RESULT

The useful game-derived kernel is not XP, quests, badges, loot or gamification.

It is:

`DISCOVER → FORECAST → ACT → LEAVE TRACE → RETURN RESIDUE → SALVAGE SCAFFOLD → RE-ENTER WITH MORE CAPABILITY`

Each verb already has or is gaining a non-game FIELD owner. No universal Game Layer is authorized.
