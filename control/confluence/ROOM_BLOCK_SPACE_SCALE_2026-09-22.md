## 0. Correction

ROOM 0.1 answered the wrong question too literally.

It showed that one FIELD identity could survive six spatial relation faces. That is a valid representation proof, but it does **not** satisfy the older FURNISHER / SINDER / FU ambition. A cube with forms on faces is not a new computing substrate.

The stronger recurring question is:

> What if physical and digital configurations were made from the same small compositional grammar, so that a useful arrangement could be inspected, changed, folded into a reusable unit, forked, replayed, materialized in another medium and returned with evidence?

That is the target for 0.2.

## 4. IMPLEMENTED — SPACE SCALE 0.2

### 4.1 BLOCK ⇄ ROOM

A primitive has stable identity, typed ports and an operator.

A composite is not a screenshot or flattened export. It contains the child identities and exposes proxy boundary ports that resolve back to the original child ports.

From outside:

```
┌──────────── FURNISHER COMPILER ────────────┐
CONSTRAINT in                         EVIDENCE out
└────────────────────────────────────────────┘
```

At ROOM scale / ENTER:

```
CONSTRAINT → SEARCH → COMPILE → VERIFY → EVIDENCE
```

Both are the same computational object.

### 4.2 Semantic zoom

```
GLYPH
  object identity / coarse topology

BLOCK
  label / typed boundary / operator role

ROOM
  implementation / children / seams / evidence
```

Zoom changes **operational granularity**.

It is not CSS magnification pretending to be semantic zoom.

### 4.3 Typed docking

A seam exists only when:

```
OUT → IN
type(A) == type(B)
or one side explicitly declares ANY
```

An already-bound input rejects a second driver.

No connection is created merely because two shapes touch.

### 4.4 FOLD

Select multiple siblings → FOLD.

The primitive graph stays intact.

The new composite derives:

- child membership;
- physical bounds in the current projection;
- free / externally connected boundary ports;
- proxy mappings back to child ports.

Therefore abstraction is reversible and inspectable.

### 4.5 FORK

A node or composite subtree can be cloned together with its internal seams.

That gives a cheap counterfactual branch:

```
CONFIG A
   ↘ fork
    CONFIG B
```

No Git terminology is required to try a different local configuration.

### 4.6 RUN

0.2 contains a deliberately small safe operator set.

There is no `eval`.

A composed graph can execute SOURCE / MAP / FILTER / MERGE / COMPILE / VERIFY / RETURN primitives and emit a dependency trace.

This is enough to test whether visible composition has consequence instead of being node-editor theatre.

### 4.7 MATERIALIZATION RECIPE

The graph can emit:

- nodes;
- typed ports;
- operators;
- topology;
- composite membership;
- placement hints.

It explicitly says:

`DECLARATIVE RECIPE ONLY · physical fit/load/safety not inferred`

Future physical compilers may consume this format after their own reality / safety gate.

### 4.8 RETURN

RETURN records:

- graph identity;
- nodes / seams;
- composites;
- view / semantic scale;
- interaction events;
- materialization recipe;
- residue.

The configuration is therefore recoverable without making the canvas canonical.

## 6. WHAT THIS ENABLES IF IT SURVIVES

This is the interesting future tree:

```
DIGITAL GRAPH
     │
     ├── semantic zoom → contextual tools
     ├── FOLD → reusable operator
     ├── FORK → counterfactual configuration
     ├── projection → map / ring / room / path / text
     ├── recipe → physical compiler
     │               │
     │               ├── printable joint witness
     │               ├── rail / panel / cassette layout
     │               ├── sensor / power / data path
     │               └── analog mark / moiré / stress witness
     │
     ├── live adapter → HOUSEBUS / HA only after authority gate
     └── RETURN → replay / compare / share
```

A future physical block does not need a screen.

Its port type could be witnessed by geometry, tactile keying, conductive coding, optical marks, color, sound, NFC, resistance or combinations of these.

A physical assembly could therefore expose enough of its own "program" to be inspected and partially verified without a central UI.

That is closer to the old claim of a human-scale multidimensional breadboard.

## 7. FAILURE CONDITIONS

Kill or demote the canvas if:

- semantic zoom is only visual novelty;
- people cannot predict what FOLD preserves;
- hidden internal semantics make a composite less inspectable than a plain list;
- typed ports become bureaucratic metadata rather than preventing real errors;
- FORK is less useful than ordinary duplicate/edit;
- physical recipes cannot acquire independent evidence / fit gates;
- the system starts demanding everything be represented as a node graph.

The transferable core can survive even if this particular canvas does not.
