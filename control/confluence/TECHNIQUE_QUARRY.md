# TECHNIQUE QUARRY

Status: **quarry / back pocket**
Updated: **2026-09-20**

This is where potentially powerful cross-domain strategies, theorems, research tangents, formalisms and odd useful ideas wait **without becoming architecture by enthusiasm alone**.

## Admission rule

Capture a technique when at least one of these is true:

- it gives a sharper way to identify, compare or transform existing objects;
- it may compress several recurring mechanisms without erasing their differences;
- it suggests a falsifiable experiment or representation;
- it repeatedly reappears across domains;
- losing it would create avoidable rediscovery cost.

Admission does **not** imply adoption.

Each item should retain:

```
NAME
SOURCE / LINEAGE
MECHANISM
POSSIBLE TRANSFER
NON-CLAIM / FAILURE MODE
CHEAPEST TEST
STATUS = QUARRY | TESTING | DONOR | ADOPTED | REJECTED
```

## Seed 01 — Yoneda lemma

**Status:** QUARRY

**Mechanism candidate:** an object can be characterized by the pattern of morphisms into/out of it; identity becomes legible through its lawful relations to probes rather than only through an internal description.

**Possible transfer:**
- FIELD INDEX capability/address queries;
- distinguishing an object from one projection of it;
- testing whether two apparently different artifacts are actually behaviorally/relationally equivalent;
- interface-first descriptions of people/devices/projects without claiming an exhaustive essence;
- "what can interact with this, and how?" as an identity probe.

**Non-claim:** FIELD is not "an implementation of Yoneda." Similarity is currently heuristic. Do not retrofit category-theory vocabulary onto systems unless it produces a concrete discriminating test or useful transformation.

**Cheapest test:** choose one existing FIELD object and describe it twice:
1. by stored attributes;
2. by the family of queries/ports/transformations through which other things can lawfully interact with it.

Compare what becomes visible or recoverable in each representation.

## Seed 02 — Lenses / optics

**Status:** QUARRY

**Mechanism candidate:** disciplined projection + update laws: view part of a state, modify through the view, and preserve coherent relation to the source.

**Possible transfer:** Scale Lens, unequal projections, editable views, Field Intake, CASE state updates, House spatial projections.

**Non-claim:** a visual "lens" metaphor is not enough; useful transfer requires explicit get/put-style laws or equivalent update invariants.

## Seed 03 — Sheaf / gluing intuition

**Status:** QUARRY

**Mechanism candidate:** local views may agree on overlaps yet fail to define one coherent global state; gluing requires compatibility conditions.

**Possible transfer:** cross-thread recovery, multi-agent context, House zone state, fragmented family/health histories, repo lineage reconstruction.

**Non-claim:** use only if overlap/compatibility tests outperform ordinary provenance + conflict handling.

## Seed 04 — Truth-maintenance systems

**Status:** QUARRY / HIGH RELEVANCE

**Mechanism candidate:** beliefs carry justifications; contradictions and revisions update dependent conclusions instead of overwriting history.

**Possible transfer:** RETRIEVAL / CANON, CONTINUITY / CASE, research synthesis, plan changes.

**Cheapest test:** extend one case packet with explicit `SUPPORTED_BY`, `CONTRADICTS`, and `SUPERSEDED_BY` edges and check whether revision becomes materially safer than flat claims.

## Seed 05 — Active information gain

**Status:** QUARRY / HIGH RELEVANCE

**Mechanism candidate:** choose the next observation/question that is expected to reduce the most consequential uncertainty, rather than merely collecting more data.

**Possible transfer:** case gaps, medical questions, House measurements, repair diagnosis, artifact archaeology.

**Non-claim:** "information gain" must not become fake numerical precision where probabilities are unavailable; ordinal ranking is often enough.

## Promotion rule

A quarry item may move toward current architecture only after:

1. named existing problem;
2. exact mechanism proposed;
3. cheapest discriminating test;
4. comparison against a boring baseline;
5. evidence of improved recovery, coordination, transformation or RETURN.

Otherwise leave it here.


## Seed 06 — Game-scale state machines

**Status:** QUARRY / HIGH RELEVANCE

Research packet: [GAME-SCALE STATE DONORS](../research/GAME_SIMULATION_STATE_DONORS_2026-09-22.md)

**Mechanism candidate:** large simulations remain tractable by separating static definitions, persistent facts, runtime effects, gates/conditions, shared current-state blackboards, projections and presentation owners.

**Donors:** Cyberpunk 2077 / REDengine quest facts + TweakDB + blackboards + effects; RimWorld Hediffs; Dwarf Fortress body/tissue-targeted syndromes; Project Zomboid event→body-part damage; Unreal Gameplay Ability System.

**Possible transfer:** CONTINUITY facts/events, CARE measurement/condition/gate separation, BODY addresses, HUMAN PORT object passage, FIELD CURRENT/RETURN distinction.

**Critical anti-transfer:** game engines own the simulated ground truth. Real-world CARE does not. Never map “unset” to false/zero, never invent biological severity thresholds, and never let a derived current projection overwrite source evidence.

**Cheapest test:** one real CARE case containing one observation, one measurement, one Port evidence object and one sourced IF/WHEN gate; require BODY/FOLLOW, BRIEF, Port and Intake projections to agree on the same underlying facts without copying or silent mutation.
